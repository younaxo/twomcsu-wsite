# TwoMC Bridge (плагин, срез «выдача заказов»)

Плагин опрашивает сайт, получает задания выдачи и исполняет разрешённые команды консолью сервера в главном потоке.
Контракт: `docs/stage-03/BRIDGE-CONTRACT.md`, раздел 14. Статус: код написан, сборка и тесты НЕ запускались (см. ниже).

## Установка

- Сервер Paper/Spigot 1.21.4, Java 21. LuckPerms необязателен (softdepend), нужен только для `lp`-товаров.
- Сборка на раннере (JDK на рабочей машине не нужен): `docker build --target artifact --output type=local,dest=out plugins/bridge`.
  Тесты JUnit входят в `gradle build`; упавший тест прерывает сборку.
- Положить `TwoMCBridge-0.1.0.jar` в `plugins/`, запустить сервер, отредактировать `plugins/TwoMCBridge/config.yml`, `/twomcbridge status`.

## Конфигурация (`delivery.*`)

| Ключ | Назначение |
| --- | --- |
| `enabled` | по умолчанию `false`; включать после выдачи ключа владельцем и включения delivery у сервера на сайте |
| `siteUrl` | адрес сайта без пути; `http` только для localhost (env `TWOMC_BRIDGE_URL`) |
| `keyId` | `<slug сервера>.<поколение>`, например `survival.1` (env `TWOMC_BRIDGE_KEY_ID`) |
| `keyFile` | файл с секретом (первая строка, 64 hex), относительно папки плагина (env `TWOMC_BRIDGE_KEY_FILE`) |
| переменная `TWOMC_BRIDGE_KEY_HEX` | секрет напрямую из окружения, приоритет над файлом |
| `extraTemplates` | дополнительные проверяемые формы команд (рекомендуется) |
| `extraRoots` | корень целиком, без проверки аргументов; нельзя для корней из белого списка по умолчанию |
| `maxPerClaim` | заданий за опрос, 1..10 (по умолчанию 5) |
| `keyRetentionDays` | срок хранения журнала ключей, не меньше 60 |

Секрет в `config.yml` не кладётся. Файл ключа: права 600, вне репозитория. На POSIX права проверяются при загрузке; шире 600 это
предупреждение в логе (на Windows проверка невозможна). Ключ создаёт и выводит только владелец командой `bridge:print-key`;
сверку ключа с выводом `bridge:print-key` выполняет владелец (формат вывода не проверялся). Агенты ключи не получают.

## Команды

Право `twomc.bridge.admin` (по умолчанию op).

- `/twomcbridge status` показывает состояние журнала, число ключей, ack в очереди, заданий в работе, паузу, последнее событие.
- `/twomcbridge forget <idempotencyKey>` убирает ключ с исходом UNKNOWN после ручной проверки (разбор неизвестного исхода).
- `/twomcbridge ackcorrupt` подтверждает повреждение журнала (см. ниже); без него выдача остановлена.

## Модель отказов

- Журнал идемпотентности: перед исполнением пишется `S` (started, fsync), после исполнения `D` (done). Задание с ключом
  в `D` не повторяется, ответ `done`.
- Ключ в `S` без `D` (сбой между запуском и итогом) это UNKNOWN: команда НЕ повторяется, ack `unknown` с кодом
  `outcome_unknown`. Игрок получил или не получил товар, определяет администратор вручную, затем `forget`.
- Исключение из `dispatch` даёт UNKNOWN (`dispatch_exception`).
- Повреждённый журнал: выдача fail-closed (стоп) до `/twomcbridge ackcorrupt`; сайт получает `retry`, а не `failed`.
- Ошибка записи журнала до запуска команды: ack `retry` (`store_unavailable`), команда не исполнялась.
- R167: команда исполняется только если ключ записан в журнал до dispatch; сайт не получает `done` раньше, чем `D`.
- Отказ локальной проверки команды даёт `failed` с кодом `command_not_allowed` / `command_invalid` / `command_forbidden`,
  в журнал не пишется, команда не исполняется.

### Трактовка `dispatchCommand == false` (L1)

`Bukkit.dispatchCommand` возвращает `false`, если команда не найдена или плагин вернул `false` (часто неверные
аргументы). Это НЕ доказывает, что побочных эффектов не было. Плагин трактует `false` как `failed` с кодом
`command_rejected`, но администратору следует проверять такие случаи вручную до повтора заказа.

## Белый список и шаблоны (M4)

Белый список по умолчанию включён и проверяет ФОРМУ команды, а не только корень:

```
lp|luckperms user <ник> parent add|addtemp <группа> [срок]
eco give <ник> <число>
give <ник> <предмет> [кол-во]
crate|cratekey key give <ник> <ключ> [кол-во]     (и cratekey give <ник> <ключ> [кол-во])
```

Например `lp user Steve permission set a.b true` отклоняется. Это допущение Q112, оно строже сайта, который сверяет
только корень (`apps/api/src/modules/delivery/command-template.ts`). Лишний слой защищает от подмены строки в БД или канале.

Расширение: `extraTemplates`, например `"kits give {nick} {key}"`. Синтаксис: слова через один пробел, первое слово корень,
`a|b` литералы, типы `{nick} {group} {key} {duration} {int} {qty} {num} {item}`, суффикс `?` у хвостовых аргументов.
Запрещённые корни (op, stop, execute, sudo и др.) не разрешаются никак. Корень нового шаблона добавьте и в расширение
корней в настройках сайта, иначе сайт не отрендерит такой товар.

## maxPerClaim и fsync в главном потоке

Журнал пишется с fsync синхронно в главном потоке (так гарантируется порядок «запись, затем команда»). Каждое задание
стоит одного fsync до и после команды, поэтому `maxPerClaim` ограничивает длительность тика выдачи: держите значение
небольшим (по умолчанию 5), на медленных дисках уменьшайте.

- Проверено: ревью кода, статический разбор escape-последовательностей строк, сверка DEFAULT_ROOTS/FORBIDDEN_ROOTS с сайтом.
- НЕ проверено: компиляция, юнит-тесты (`CommandPolicyTest`, `DeliveryEngineTest` и др.), сборка jar, запуск на сервере.
  JDK и раннер были недоступны. Первый запуск `docker build` на раннере может выявить ошибки компиляции.
- НЕ проверено: интеграция с реальным LuckPerms/EssentialsX/crate-плагином, формат вывода `bridge:print-key`.

## Риски

- Dockerfile использует тег `gradle:8.14.5-jdk21`. На раннере нужно сверить, что тег существует, и при желании закрепить
  `@sha256`-дайджест. Тег не менять без решения chief.
- Зависимость `org.spigotmc:spigot-api:1.21.4-R0.1-SNAPSHOT` с SNAPSHOT-репозитория Spigot: сборка не воспроизводима
  побайтно, репозиторий может быть недоступен или изменить артефакт. Рекомендуется закрепить версию или зеркало.
- Исполнение консольных команд по сети: безопасность держится на HMAC-ключе сервера, белом списке форм и журнале.
