# Промпт для Claude Design — twomc.su

> Скопируйте текст ниже целиком в Claude Design. Файл `CLAUDE-DESIGN-
> BRIEF.md` из этой же папки нужно приложить/вставить вместе с промптом
> (он слишком большой, чтобы пересказывать своими словами — это полное
> функциональное ТЗ).

---

Спроектируй дизайн-систему и ключевые экраны веб-сайта Minecraft-
сообщества twomc.su на основе приложенного функционального ТЗ
(`CLAUDE-DESIGN-BRIEF.md`).

Это ТЗ описывает уже работающий backend (NestJS, реальные API,
покрытые тестами) — ничего из бизнес-логики там не придумано, это факт
текущей реализации. Твоя задача — спроектировать визуальный дизайн и
UX поверх этого функционала, а не придумать функционал заново.

Пожалуйста:

1. Предложи дизайн-систему: типографику, цветовую палитру (включая
   тёмную/светлую тему и семантические цвета — успех/ошибка/
   предупреждение/редкости достижений/статусы заказов), сетку и
   spacing-шкалу, иконографию, responsive-брейкпоинты. Стиль, настроение
   и конкретные значения — полностью на твоё усмотрение; в ТЗ
   сознательно нет визуальных указаний.
2. Спроектируй библиотеку компонентов из раздела 7 ТЗ со всеми
   состояниями из раздела 4 (default/loading/skeleton/empty/error/403/
   404/offline/maintenance/success/validation error/disabled/locked).
3. Спроектируй информационную архитектуру и навигацию (раздел 2 ТЗ) —
   отдельное внимание на **динамическое, permission-driven меню
   админки** (раздел 1.1, 2.3): набор видимых разделов зависит от
   фактических прав пользователя, а не фиксирован по роли.
4. Спроектируй ключевые экраны по каждому разделу из раздела 3 ТЗ —
   как минимум: публичный профиль, магазин (каталог/товар/корзина/
   checkout), обращения (создание + очередь модератора), чат, личные
   сообщения, достижения/рейтинги, и из админки — дашборд, список
   пользователей с bulk-действиями, управление ролями/permissions
   (матрица), audit log.
5. Проиллюстрируй минимум 3 сквозных user flow из раздела 5 ТЗ как
   последовательность экранов/состояний (например: магазин → заказ;
   жалоба → модерация → наказание; назначение роли).
6. Используй реалистичный контент на русском языке в духе Minecraft-
   сообщества (раздел 9 ТЗ) — без Lorem Ipsum.
7. Если в процессе возникнет идея новой бизнес-функции (не описанной в
   ТЗ) — вынеси её отдельным явным пунктом "Предложение для бизнес-
   логики", не закладывай молча в дизайн как часть текущего функционала
   (раздел 10 ТЗ).

Результат нужен в виде, который можно сопоставить с реальными route'ами
и компонентами для последующей реализации (экран → route → данные/API →
нужные permissions) — так что, пожалуйста, подписывай экраны их route
из ТЗ (например `/store/checkout`, `/admin/roles`).
