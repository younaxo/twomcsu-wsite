## 1–5. Модель

- Иерархия от младшей к старшей: **Dionysus → Hermes → Heracles → Apollo →
  Ares → Poseidon → Zeus**. Каждая следующая наследует ВСЁ предыдущее.
- Это НЕ staff RBAC (Owner, Chief Curator, Developer, Moderator…). Привилегия
  не даёт админку, модерацию, управление RBAC/пользователями, системные
  настройки, security-права. Отдельный слой Donation Tier / Entitlements;
  staff RBAC и donation могут быть у одного пользователя одновременно.
- Без хардкода `if (user.donation === 'ZEUS')` по проекту: централизованные
  DonationTier / DonationEntitlement / DonationTierEntitlement (или
  эквивалент), единый resolver effectiveDonationTier /
  effectiveDonationEntitlements.
- Наследование настоящее (ZEUS inherits POSEIDON … HERMES inherits DIONYSUS),
  без копирования сотен строк прав.
- Числовые параметры — OVERRIDE, не сумма: берётся наибольшее значение
  действующей цепочки (ивенты, скидка, множитель передачи рубинов, лимиты,
  количество шрифтов, цветов, украшений, эффектов и т.п.). Пример: Ares 1/нед,
  Poseidon 1/сутки, Zeus 3/сутки → у Zeus 3/сутки.

## 22–30. Системы

- **Шрифты ника:** Hermes 3, Heracles 5, Apollo 7, Ares 10, Poseidon 15,
  Zeus 18; старший включает шрифты младших; только своя approved font library,
  без загрузки пользовательских файлов шрифтов.
- **Цвета ника:** Apollo 3, Ares+ минимум 5, Poseidon/Zeus — доп. premium
  palettes; только approved palette, без CSS injection; читаемость в Dark и
  Light.
- **Украшения профиля:** интеграция с полноценным модулем Decorations (catalog
  / ownership / equip), не отдельная donation-копия; количество и наборы — по
  tier.
- **Эффекты профиля:** Zeus — 3 эксклюзивных; Poseidon и ниже — меньшие наборы
  по конфигурации; производительно, reduced-motion, mobile fallback, не мешают
  accessibility и кликам.
- **Карта:** Poseidon — просмотр; Zeus — карта + игроки; Zeus может скрыть
  своё местоположение; права карты server-side (не скрытие маркеров CSS).
- **Инвентарь:** Apollo+ — просмотр по правам/приватности; Poseidon+ — скрыть
  свой; Ares+ — Ender Chest; Poseidon+ — скрыть Ender Chest; одно server-side
  решение с учётом owner, friends/privacy, donation entitlement, staff
  permission.
- **Custom profile slug (Ares+):** уникальность, lowercase/нормализация,
  reserved words (admin, api, login, register, shop, store, mini-games,
  settings, support, status и системные маршруты), защита от мата/abuse,
  длина, rate limit, cooldown, audit, редиректы со старого URL (если
  архитектура позволяет).
- **Скрыть привилегию (Ares+):** только отображение; entitlement продолжает
  работать; staff с правом видит реальный tier; нельзя использовать для обхода
  модерации/аудита.
- **Скидки:** Ares 5%, Poseidon 7%, Zeus 10% — server-side в pricing engine,
  не доверять цене с фронта, не промокод; в snapshot заказа хранить base
  price, discount source, discount amount, final price.

## 31–38. Ограничения и прочее

- **Никакого pay-to-win в случайности:** убрать идею x2/x3 шанса в мини-играх;
  не увеличивать вероятность выигрыша в розыгрышах за плату.
- **Безопасные бонусы мини-игр:** доп. бесплатные attempts (если механика
  позволяет), косметические награды, profile XP/points, сниженный неигровой
  cooldown (без влияния на исход ставки), визуальные эффекты, отдельная
  история/аналитика, косметические достижения. НИКАКОГО «Zeus chance ×3».
- **Розыгрыши:** odds не меняются; можно эксклюзивные косметические
  розыгрыши, donation-only cosmetic draws, eligibility-кампании без денежных
  ставок, спец-badges.
- **Приоритет поддержки:** Heracles+ priority, Poseidon — повышенный, Zeus —
  максимальный; в backend обращений — priority level и сортировка очереди;
  staff может вручную повысить приоритет.
- **Лимит друзей:** централизованная конфигурация base … Zeus, настраивается
  в админке (если позволяет архитектура), без случайных чисел в UI.
- **Лимиты загрузок:** banner, profile media, вложения сообщений могут расти
  по tier, но всегда есть server-side максимум; tier никогда не отключает
  проверку MIME/magic bytes.
- **Badges:** у каждого tier свой donation badge (не путать с PNG prefix и
  store art); единое отображение в публичном профиле, mini-profile,
  комментариях, друзьях, чате, рейтингах — где контекст разрешает badges.
- **Donation prefixes:** проверить наличие отдельных Minecraft prefix assets;
  store artwork не использовать как маленький inline prefix; если prefix-
  ассетов нет — mapping/fallback без искажения store artwork.

## 39–53. Админка, аудит, права

- **Админка → «Донат / Привилегии»:** список tiers, иерархия, capabilities,
  numeric limits, визуальные ассеты, enabled/disabled, связь с товаром
  магазина, скидки, квоты ивентов, множитель передачи рубинов, шрифты, цвета,
  decorations/effects, privacy capabilities.
- **Защищённые ключи** DIONYSUS, HERMES, HERACLES, APOLLO, ARES, POSEIDON, ZEUS
  — не удалить; конфигурацию менять можно, иерархию ломать нельзя.
- **Назначение/снятие tier** администратором с отдельным правом: проверка
  полномочий, подтверждение, audit, причина, дата начала, дата окончания (если
  применимо); не связано с редактированием staff-ролей.
- **Сроки:** permanent, startsAt, expiresAt; после expiresAt tier
  автоматически перестаёт действовать.
- **Upgrade/downgrade** Dionysus → … → Zeus: не 7 независимых продуктов с
  конфликтующими entitlements; source of truth — один effective tier.
- **Несколько покупок:** effective = самый высокий активный; скидки не
  складываются.
- **Профиль:** в публичном профиле и mini-profile показывать tier (если не
  скрыт): badge, название, visual identity — аккуратно, без рекламного баннера.
- **Настройки привилегии:** «Моя привилегия», срок действия, полученные
  возможности и разрешённые настройки (privacy, fonts, colors, banner,
  decoration, effect, custom URL, map privacy, inventory privacy и т.д.).
- **Locked state:** не просто скрывать — где полезно, «Требуется Ares» /
  «Доступно с Poseidon», без агрессивного upsell.
- **Server-side enforcement** всех возможностей; нельзя вручную через API:
  получить скидку, сменить custom URL, скрыть маркер карты, прочитать чужой
  инвентарь, перевести повышенный объём рубинов, стартовать ивент,
  использовать locked font.
- **Безопасность старта ивента:** entitlement, quota, cooldown, разрешённый
  ивент, состояние сервера, уже идущий ивент, maintenance, конкурентность,
  idempotency; audit: кто, какой ивент, когда, какая привилегия, результат.
- **Безопасность передачи рубинов:** получатель существует; не себе (без
  отдельной причины); amount > 0; достаточный баланс; effective limit; дневная
  квота; rate limit; idempotency; транзакция; ledger; fraud/security events;
  без floating point.
- **Аналитика (реальная, право на просмотр):** число активных tiers,
  распределение, покупки, истечения, использованные скидки, передачи рубинов,
  старты ивентов, использование функций.
- **Audit:** назначение, снятие, override истечения, изменения конфигурации,
  скидок, квот ивентов, передачи рубинов, иерархии, защищённых настроек.
- **Права админки** (привести к naming convention): `donations.view`,
  `donations.manage`, `donations.assign`, `donations.config.edit`,
  `donations.statistics.view`.
