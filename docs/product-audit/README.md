# Product Completion Audit — twomc.su

Цель: сравнить старый сайт (`github.com/younaxo/twomcsu-website`, состояние
на коммит `e62750f` от 2026-09-23) с новым (`younaxo/twomcsu-wsite`, `main`
после PR #62) и определить, что нужно, чтобы новый сайт стал полноценным
продуктом, а не набором API и экранов админки.

## Метод

1. **Опись старого сайта** (`INVENTORY-OLD.md`): все пользовательские и
   админские функции по доменам 1–8, с путями к коду и оценкой зрелости.
   Функции-заглушки старого сайта (моки, фейковые данные) не переносятся
   как есть — переносится только смысл.
2. **Опись нового сайта** (`INVENTORY-NEW.md`): что реально доступно
   пользователю и админу; отдельно — «API есть, интерфейса нет».
3. **Разрывы** (`GAP-ANALYSIS.md`): по каждому домену — чего не хватает,
   приоритет и откуда брать требования.
4. **Roadmap** (`ROADMAP.md`): реализация волнами, каждая — вертикальными
   срезами (API → web → тесты → документы → PR).

## Домены

1. Account / Profile / Settings / Security
2. Social
3. Content
4. Store
5. Minecraft / Stats / Achievements / Decorations / Gamification
6. Mini-games (`/mini-games`: Апгрейдер, Рулетка, Краш)
7. Admin
8. System / QA

## Шкалы

Зрелость: **полностью** (API + UI + тесты), **только API**, **только UI**,
**частично**, **нет**.

Приоритет разрыва:

- **P0** — без этого продукт не работает для игрока (вход, профиль, магазин,
  базовая социальность);
- **P1** — ожидаемая функция старого сайта или ТЗ владельца;
- **P2** — улучшение, можно позже.

## Правила

- Никаких фейковых данных и функций: если нет источника (плагин, платёжка,
  CDN-ассеты), функция помечается 🚫 с указанием, что нужно от владельца.
- Дизайн — «Полдень» (`/design-lab`), без glass; все модалки — production
  Dialog.
- Каждая волна — отдельные PR с зелёным CI, ADR на нетривиальные решения.
