# ROADMAP — реализация волнами

Основа: `GAP-ANALYSIS.md`. Волна — домен, срез — вертикальная поставка:
**API (если нужно) → web UI → тесты → документы → отдельный PR** (ветка
`feature/<срез>`, зелёный CI: lint, typecheck, unit, e2e, build, CodeQL,
gitleaks). Внутри волны срезы идут по приоритету: P0 → P1 → P2.

## Общие требования к каждому срезу

- **Дизайн**: «Полдень» (`/design-lab`, ADR-0055), без glass и
  `backdrop-filter`. Примитивы — `apps/web/src/components/ui/*`.
- **Модалки**: только production `Dialog` / `AlertDialog` / `ConfirmDialog` /
  `Sheet` из `components/ui` (ADR-0064). Никаких `window.confirm` и самодельных
  оверлеев.
- **Недоступное**: курсор `not-allowed` (ADR-0075) и подсказка с причиной.
  Функции, которых ещё нет, не показываются как рабочие.
- **Данные**: никаких фейковых данных и цифр. Нет данных — честный
  `EmptyState`. Нет внешнего источника — 🚫 и сообщение владельцу.
- **Доступ**: новые права — в `packages/shared/src/permissions.ts` и сиде ролей
  (ADR-0051). Новые разделы — в реестре модулей (ADR-0082) и под `ModuleGate`.
- **Контракт**: DTO — в `packages/shared/src/api/*`.
- **Качество**: адаптивность 375–1920 (`RESPONSIVE-AUDIT.md`), клавиатура и
  фокус, `prefers-reduced-motion`.
- **Документы**: `CHANGELOG.md`, `STATUS.md`, ADR в `DECISIONS.md` на
  нетривиальные решения, `RISKS.md` при новом внешнем блокере.

**Готово (общий DoD)**: функция проходит сценарий в браузере на реальном API;
все состояния (загрузка, пусто, ошибка, нет прав, модуль выключен)
реализованы; тесты покрывают API-изменения (e2e) и UI-логику (Vitest); PR
слит.

## Волна 1. Account / Profile / Settings / Security

### 1.1 Настройки аккаунта: профиль, приватность, соцсети, аватар и баннер — P0

Ветка `feature/account-settings` (в работе, не в `main`).

- **Цель**: игрок сам редактирует профиль и приватность. Сейчас всё это есть
  только в API.
- **Маршруты**:
  - `/settings` — «Профиль»: изображения, «О себе», соцсети;
  - `/settings/privacy` — «Приватность»;
  - `/settings/linked-accounts` — есть, переносится в общий layout.
  - Layout `apps/web/src/app/(site)/settings/layout.tsx`: навигация разделов
    (`SECTIONS`), `RequireSession` (`components/auth/require-session.tsx`).
- **API** (есть):
  - `GET/PATCH /users/me/profile`;
  - `GET /users/me/social-links`, `PUT/DELETE /users/me/social-links/:platform`;
  - `POST/DELETE /users/me/avatar` (до 5 МБ → 512×512), `POST/DELETE
/users/me/banner` (до 10 МБ → 1920×480), multipart (`api/files`).
- **API (доработки)**:
  1. `birthDate: null` очищает дату (`profiles.service.ts`, в работе).
  2. `avatar` в `MeResponse` (`packages/shared/src/api/auth.ts:71`) и в
     `GET /auth/me`, чтобы `components/shell/profile-trigger.tsx` показывал
     аватар, а не инициалы.
  3. Проверка формата ссылки соцсети по платформе (ответ 400 с понятным
     сообщением для поля).
- **Web**:
  - `app/(site)/settings/page.tsx`, хуки `lib/account/hooks.ts`
    (`useOwnProfile`, `useUpdateProfile`, `useSocialLinks`,
    `useSaveSocialLink`, `useProfileImage`), типы
    `packages/shared/src/api/account.ts`;
  - поле изображения: `components/ui/file-dropzone.tsx` + превью,
    «Удалить» через `ConfirmDialog`, лимиты размера показаны до выбора файла;
  - «О себе»: `Field`, `Input`, `Textarea` (статус, о себе), `Select` (пол),
    `DatePicker` (ADR-0076), `Switch` «Показывать дату рождения»;
  - соцсети: поле на платформу, сохранение по полю, ссылки открываются через
    `external-link-guard` (ADR-0060);
  - `app/(site)/settings/privacy/page.tsx`: `RadioGroup` для
    `profileVisibility` (все / друзья / никто), `friendRequestPolicy`,
    `directMessagePolicy`, `commentPolicy`; `Switch` для `hide*` и
    `commentsEnabled`. Подписи честно говорят, что именно скрывается.
- **Ключевые требования**:
  - каждая секция сохраняется отдельно;
  - кнопка «Сохранить» активна только при изменениях; пока запрос идёт или
    форма невалидна — `disabled` + `not-allowed`;
  - ошибки API привязаны к полям;
  - после сохранения обновляются `/auth/me` и превью профиля (query-ключи).
- **Тесты**:
  - e2e: `profiles.e2e-spec.ts` (очистка `birthDate`, валидация соцсетей),
    `files.e2e-spec.ts` (лимиты размера и типов);
  - Vitest: формы профиля и приватности (валидация, dirty-state, ошибки).
- **Документы**: `CHANGELOG.md`, `STATUS.md`.
- **Блокеры**: 🚫 S3 (R3) — загрузка в production. В dev работает драйвер
  `local`.
- **Готово, когда**: все поля сохраняются и подтягиваются после перезагрузки;
  аватар виден в шапке без перезагрузки; пункт меню «Настройки» ведёт сюда.

### 1.2 Безопасность: смена пароля и мои сессии с отзывом — P0

Ветка `feature/account-security`.

- **Цель**: игрок меняет пароль и управляет сессиями.
- **Маршрут**: `/settings/security` — новый раздел в `SECTIONS`.
- **API** (есть):
  - `POST /auth/change-password` (`currentPassword`, `newPassword` 8–72);
  - `GET /auth/sessions`, `DELETE /auth/sessions/:id`, `DELETE /auth/sessions`.
- **API (доработки)**:
  1. **Текущая сессия.** При выпуске access-JWT (`auth.service.ts:319`, сейчас
     только `sub`) добавить `sid` — id `RefreshToken`. В `SessionSummary`
     добавить `current: boolean`.
  2. **Отзыв при смене пароля.** В `ChangePasswordDto` — `revokeOtherSessions`
     (по умолчанию `true`): отзываются все refresh-сессии, кроме текущей.
  3. **Своя сессия.** `DELETE /auth/sessions/:id` для текущей сессии
     отвечает 400 с подсказкой «используйте выход».
  4. **Уведомление** «Пароль изменён» с типом `SYSTEM`.
  5. **`mustChangePassword`.** Если флаг стоит — редирект на
     `/settings/security` с баннером.
- **Web**:
  - **Форма смены пароля.** `components/auth/password-field.tsx`: текущий,
    новый, повтор; правила длины видны сразу; флажок «Завершить другие
    сессии» (включён).
  - **Список сессий.** Карточка: устройство и браузер из `userAgent` (разбор
    на клиенте, без внешних сервисов), IP, «создана», «истекает», метка «Это
    устройство».
  - **Действия.** «Завершить» и «Выйти на всех других устройствах» — через
    `ConfirmDialog`. Для текущей сессии «Завершить» не показывается.
  - **Состояния.** Загрузка, пусто, ошибка.
- **Тесты**:
  - e2e `auth.e2e-spec.ts`: флаг `current`, `revokeOtherSessions`, чужую
    сессию отозвать нельзя, текущую — 400;
  - Vitest: форма и список.
- **Документы**: ADR «Идентификатор сессии в access-токене и отзыв при смене
  пароля», `CHANGELOG.md`.
- **Блокеры**: нет.
- **Готово, когда**: после смены пароля другие устройства разлогинены, текущее
  — нет; пункт меню «Безопасность и сессии» ведёт сюда.

### 1.3 Публичный профиль `/u/[username]` — P0

Ветка `feature/public-profile`.

- **Цель**: у каждого игрока есть страница профиля.
- **Маршрут**:
  - `app/(site)/u/[username]/page.tsx`; `generateMetadata` — ник в заголовке,
    `noindex` для скрытых;
  - редирект `/users/:username` → `/u/:username` для ссылок старого сайта
    (`next.config`).
- **API (доработки `GET /users/:username/public`, `profiles.service.ts:89–112`)**:
  1. **`FRIENDS_ONLY`** виден принятым друзьям (`Friendship` ACCEPTED), а не
     скрыт от всех.
  2. **Блокировка** в любую сторону → профиль скрыт.
  3. **Скрытый профиль** существующего игрока → 200 `{ username, hidden: true }`,
     как `GET /users/:username/summary` (ADR-0073). 404 — только для
     несуществующего ника.
  4. **Состав ответа.** Добавить с учётом приватности:
     - основная роль (префикс), позиция, кастомная позиция, отделы;
     - активные бейджи, награды, витрина достижений;
     - статистика (с `hideStatistics`), ник привязанного Minecraft-аккаунта;
     - число друзей и выполненных достижений, дата регистрации;
     - выбранное украшение (для 5.3).
  5. **Контракт**: `PublicProfileDto` в `packages/shared/src/api/users.ts`.
  - Жалоба: `POST /users/:username/report` (есть).
- **Web**:
  - **Шапка (`ProfileHeader`)**: баннер (`ProtectedImage`), `Avatar` (`lg`),
    `UserIdentity` с `RolePrefix`, статус, копирование `#shortId`;
  - **`ProfileAbout`**: о себе, страна, город, пол, день рождения — только
    разрешённое;
  - **`ProfileStats`**: блок только при реальных данных, нулей-заглушек нет;
  - **`ProfileSocials`**: через `external-link-guard`;
  - **бейджи, награды, витрина** — только чтение;
  - **действия**: владелец — «Редактировать профиль» → `/settings`; гость —
    «Пожаловаться» (`Dialog` с причиной). «В друзья» и «Написать» появятся в
    волне 2 и до неё не показываются;
  - **состояния**: скрытый профиль (`HiddenProfile`), `notFound()`, загрузка,
    ошибка;
  - **превью** (`components/profile/profile-preview.tsx`) получает ссылку
    «Открыть профиль».
- **Тесты**:
  - e2e `profiles.e2e-spec.ts`: `FRIENDS_ONLY` для друга и не-друга,
    блокировка, скрытый → 200 `hidden`;
  - Vitest: состояния страницы (скрыт, владелец, нет статистики).
- **Документы**: ADR «Видимость FRIENDS_ONLY, блокировки и скрытое состояние
  профиля», `CHANGELOG.md`.
- **Блокеры**: 3D-скин — не в этом срезе. Источник скинов (`mc-heads.net`,
  как в старом, или свой) решает владелец.
- **Готово, когда**: профиль любого игрока открывается из превью, меню и
  ссылок `/users/*`; приватность соблюдается на сервере.

## Волна 6. Mini-games (`/mini-games`: Апгрейдер, Рулетка, Краш)

Требования честности, валюты, лимитов и аудита — `GAP-ANALYSIS.md`, раздел
«Мини-игры». Слово «Казино» в UI не используется.

### 6.0 Решения владельца и ADR — приняты (2026-10-10), волна НЕ заблокирована

- **Решение владельца (2026-10-10)**:
  - Апгрейдер — на **предметах** (зависит от предметов волны 5: украшения);
  - Рулетка — на **рубинах**;
  - Краш — на **рубинах**;
  - рубины на текущем этапе — **внутренняя валюта twomc.su**.
- **Запрещено добавлять самостоятельно**: cash-out, обмен рубинов обратно на
  реальные деньги, вывод предметов в деньги, P2P-вывод стоимости и любые другие
  механики обратного денежного обмена. «Забрать» в Краше — это фиксация
  множителя раунда в рубинах, а не вывод денег.
- **Отложено (product/legal, не блокирует разработку)**: можно ли покупать
  рубины за реальные деньги.
- **Можно делать**: ADR, `MiniGamesModule`, кошелёк и журнал проводок рубинов,
  транзакции, Апгрейдер, Рулетку, Краш, realtime, историю, frontend, mobile,
  админку, RBAC, audit, управление модулем, тесты, документацию.
- **Ещё нужно от владельца (уточнить в ADR, не блокер)**: house edge, лимиты,
  возрастной ценз, передача валюты между игроками — до решения безопасные
  дефолты: передачи нет, лимиты включены.
- **Результат**: ADR «Мини-игры: валюта, честность, лимиты».

### 6.1 Платформа мини-игр — P1

- **API (новое)**:
  - модуль `mini-games` в реестре (ADR-0082);
  - кошелёк (из 4.8, отдельный вид баланса);
  - `FairnessService` и модель `MiniGameSeed` (зашифрованный `serverSeed`,
    хеш, `clientSeed`, `nonce`, статус);
  - `MiniGameBet` — неизменяемая запись ставки;
  - `MiniGameSettings` по игре: включена, мин/макс ставка, макс выплата,
    edge, диапазоны;
  - сервис лимитов: дневной проигрыш, частота, самоограничение;
  - эндпоинты: `GET /mini-games`, `GET/POST /mini-games/seeds` (смена seed,
    свой `clientSeed`), `GET /mini-games/bets`, `/bets/:id` (данные для

- **Маршруты**: `/mini-games` (лобби: игры, баланс, правила), `/mini-games/fairness`

- **Тесты**:
  - unit: эталонные векторы HMAC → результат;
  - e2e: параллельные ставки без двойного списания, лимиты, выключенный
