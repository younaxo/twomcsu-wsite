# GAP-ANALYSIS — разрывы между старым и новым сайтом

Основа: `INVENTORY-OLD.md` (старый, `e62750f`), `INVENTORY-NEW.md` (новый,
`main` = `e5d86bf`). Приоритеты и правила — `README.md`: **P0** — без этого
продукт не работает для игрока; **P1** — ожидаемая функция старого сайта или ТЗ
владельца; **P2** — можно позже. 🚫 — нужен владелец (данные, ключи, ассеты,
решение); код R* — `docs/implementation/RISKS.md`.

Пути — в описях. Здесь только суть разрыва.

## Мини-игры (`/mini-games`)

### Что берём из старого сайта

Код — ничего: мини-игр в старом сайте нет (`INVENTORY-OLD.md`, домен 6). Берётся
намерение этапов «Casino» и «Daily Rewards + Wheel» (`AGENTS.md:94–97`).
Раздел называется «Мини-игры», маршрут `/mini-games`. Слово «Казино» в UI сайта
не используется. Механики — по ТЗ владельца: **Апгрейдер, Рулетка, Краш**.

### Механики (MVP)

| Игра                             | Механика                                                                                                                                                                                                                         | Честность                                                                         | Особенности                                                                                                            |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Апгрейдер `/mini-games/upgrader` | Игрок выбирает ставку `S` и целевой множитель `M` (диапазон задаёт админ, например ×1.2…×100). Шанс `P = (1 − edge) / M`. Выигрыш при `r < P` (`r ∈ [0,1)`), выплата `S × M`, иначе ставка сгорает. Шанс показывается до ставки. | Один бросок provably fair на ставку                                               | Апгрейд предметов (украшений) — P2, только для предметов без денежной стоимости и после волны 5 (🚫 решение владельца) |
| Рулетка `/mini-games/roulette`   | Одиночный спин колеса с опубликованной таблицей секторов (цвет или множитель, вероятность). Ставка на цвет или сектор. ### Валюта

- Только внутриигровая валюта **без денежной стоимости**. Реальные деньги в
  мини-играх не участвуют: ставку нельзя оплатить рублями, выигрыш нельзя
  вывести или обменять на рубли.
- Риск: в старом магазине за рубли продавались **и рубины, и монеты**
  (`seed/store-products.data.ts:252–275`, 1 ₽ = 2 рубина, 1 ₽ = 8 монет). Если
  купленная валюта попадает в ставки, а выигрыш тратится на товары, которые
  продаются за рубли, — это признаки азартной игры. 🚫 Перед стартом владелец
  проверяет соответствие законодательству и политике Mojang (ссылка уже в
  футере, `MOJANG_POLICY_URL`) и правилам платёжного провайдера.
- Рекомендация: отдельный баланс мини-игр (или раздельные балансы «куплено» и
  «заработано»). Пополнение — только игровыми способами: голосование,
  ежедневный бонус, достижения, игра на сервере после появления плагина. Баланс
  не продаётся, не конвертируется в рубины и в товары за рубли, не передаётся
  между игроками (или передаётся с жёсткими лимитами — решение владельца).
- Кошелёк — журнал проводок: баланс равен сумме проводок. Каждая операция
  идемпотентна (ключ), атомарна (транзакция с блокировкой строки кошелька),
  отрицательный баланс запрещён. Тот же кошелёк нужен для бонусов (волна 5) и
  валюты магазина (волна 4).
- Если баланс должен совпадать с игровым — нужна синхронизация через плагин
  (🚫 R20). До неё источник истины — сайт.

### Требования честности

1. **Provably fair** (основной вариант):
   - `serverSeed` — 32 байта из CSPRNG; до ставки публикуется
     `SHA-256(serverSeed)`;
   - `clientSeed` задаёт игрок (по умолчанию случайный);
   - `nonce` растёт на каждую ставку;
   - результат `r` — первые 52 бита `HMAC-SHA256(serverSeed, clientSeed:nonce)`,
     делённые на 2^52;
   - после смены seed старый раскрывается;
   - `/mini-games/fairness` пересчитывает любую ставку в браузере.
2. Краш — цепочка хешей. Публикуется последний хеш цепочки, точка краша
   раунда выводится из его хеша с учётом edge.
3. Минимально допустимая альтернатива — серверный CSPRNG
   (`crypto.randomInt`) с неизменяемым журналом результатов. Проверить её игрок
   не может, поэтому только как временная мера.
4. Публичные правила каждой игры: house edge, теоретический RTP, таблица
   вероятностей. Персональных коэффициентов и «подкрутки» нет. Изменение edge
   проходит через журнал аудита и действует только для новых ставок.
5. Никаких фейковых лент «последние выигрыши». Только реальные ставки, с
   учётом приватности профиля.

### Лимиты и ответственная игра

- Минимальная и максимальная ставка, максимальная выплата за ставку, дневной
  лимит проигрыша и числа ставок, rate limit, одна ставка на раунд краша.
- Самоограничение (лимит или пауза на срок), запрет мини-игр игроку
  отдельным permission-действием, выключатель модуля и отдельных игр
  (ADR-0082).
- 🚫 Возрастной ценз и способ подтверждения (дата рождения необязательна) —
  решение владельца.

### Аудит и анти-абьюз

- Неизменяемая запись каждой ставки: игра, ставка, параметры,
  `serverSeedHash`, `clientSeed`, `nonce`, результат, выплата, баланс до и
  после, время.
- Журнал аудита на настройки и ручные корректировки баланса (ADR-0056).
- Отчёты админки: фактический RTP против теоретического, крупные выигрыши,
  аномальная доля побед.
- Против мультиаккаунтов: начисление бесплатной валюты только с привязанным
  Minecraft-аккаунтом (один UUID — один аккаунт уже обеспечен, ADR-0072);
  подозрительные IP (`/admin/security/suspicious`); лимиты бонусов; Turnstile
  при подозрительной активности.
