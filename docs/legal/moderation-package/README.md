## Назначение

Сведённые черновики общих документов сайта и магазина TwoMC, которые обычно запрашивают при модерации у платёжного провайдера. Пакет готовит агент для владельца и юриста. Юридических выводов и заключений пакет не содержит.

Статус на дату подготовки:
- платёжный провайдер не выбран (решение D2, владелец с консультантом);
- юридический статус продавца не определён (решение D3: самозанятый, ИП или ООО);
- решение по Q79 (платное снятие бана и мута) открыто, а поправка владельца от 2026-11-17 его включает. Это противоречие вынесено в `open-questions.md`, пункт К1;
- страницы юридических документов на сайте, по черновику 08, остаются заглушками. Этот пакет на сайт не выводится.

## Чек-лист типичных требований модерации (общий)

Список типичных требований, без названия провайдера. Конкретные требования выбранного провайдера не проверялись: провайдер не выбран. Перед подачей список сверяется с документами выбранного провайдера и с юристом.

- [ ] Публичная оферта открывается по ссылке до оплаты; при оформлении есть согласие покупателя с офертой, версия и время акцепта сохраняются в заказе (`offer.md`).
- [ ] Реквизиты продавца: наименование, статус, ИНН, ОГРН или ОГРНИП (если применимо), адрес, e-mail, телефон. Вносит владелец (`drafts/04`).
- [ ] Контакты поддержки и порядок претензий, со сроком ответа (`drafts/04`, `offer.md`, раздел 10).
- [ ] Описание товаров и услуг, цены в рублях, что именно получает покупатель (`products.md`).
- [ ] Порядок и сроки выдачи цифрового товара, включая ручную выдачу (`drafts/06`, `offer.md`, раздел 5).
- [ ] Политика возвратов и отмены, с порядком подачи обращения (`refunds.md`).
- [ ] Политика обработки персональных данных и политика cookie (`privacy.md`).
- [ ] Отсутствие азартных механик: нет обещаний шансов, множителей x2/x3, перков, которых нет в игре, донат-бонусов в азартных механиках (`products.md`, раздел 5).
- [ ] Способы оплаты указаны только включённые. Список определяют провайдер и владелец (`open-questions.md`, К12).
- [ ] Сайт доступен по HTTPS на боевом домене. Это production, делает только владелец (D7).
- [ ] Ссылки из подвала ведут на все юридические страницы. Web-задача, решает chief.

## Что заполняет владелец

Агент эти поля не заполняет и не подставляет значения из конфигурации сайта (`LEGAL_OWNER` и подобные), пока владелец их не подтвердит.

- Наименование продавца `[НАИМЕНОВАНИЕ ПРОДАВЦА]`, статус `[СТАТУС ПРОДАВЦА]` (D3), ИНН `[ИНН]`, ОГРН или ОГРНИП `[ОГРН/ОГРНИП]`, адрес `[АДРЕС]`.
- E-mail поддержки и претензий `[EMAIL]`, телефон `[ТЕЛЕФОН]`, срок ответа `[СРОК]`, домен `[ДОМЕН]`, дата редакции `[ДАТА]`.
- Версия оферты `store.offerVersion` (по умолчанию 1, Q84).
- Цены и варианты каталога, срок выдачи, режим выдачи на старте (`products.md`, `offer.md`).
- Решения по Q79, по D9 (quick-buy), по рубинам, по окну возврата (D8, Q85, Q83).
- Сроки хранения персональных данных и инвентаризация моделей (`privacy.md`, раздел 3).
- Выбор провайдера (D2), способы оплаты, логотипы.
- Подача анкеты, приёмочная оплата, боевые ключи: владелец, без участия агента.

## Правила пакета

- Файлы пакета не публикуются и не отправляются провайдеру. Публикация страниц — web-срез, решает chief.
- Черновики заменяются итоговыми текстами только после решения владельца и проверки юристом. Плашка «Черновик» снимается при публикации, не раньше.
- Новые версии создаются новыми файлами рядом со старыми. Ничего не удаляется.
- Противоречия между источниками не решаются агентом. Они записаны в `open-questions.md`.
