# Промпт 16 — разовый розыгрыш «Анархия Новой Эры»

- Версия: 1.0 (2026-11-19 ~11:00). Источник: сообщение владельца в сеансе twomc-chief; текст ниже — дословно (основное задание и два дополнения).
- Открывает hard gate на розыгрыши ТОЛЬКО в объёме этого розыгрыша; разрешает деплой ТОЛЬКО мини-выкладки розыгрыша на выделенный сервер. Остальной production запрещён. Работа над сайтом (слой 0 и далее) остановлена.

---

ПРИОРИТЕТ ВЛАДЕЛЬЦА. Лимит использования ограничен, поэтому:
А. Работу над сайтом (слой 0, 0.9, runbook-и 0.10, слои 1–2, публикация прочих веток) остановить, если ещё не остановлена. Незакоммиченное сохрани WIP-коммитом (ничего не удаляя, без force-push), обнови CHECKPOINT. Экономь лимит: один исполнитель, один ревьюер Security на всю задачу, точечные тесты, без широкого обхода репозитория, короткие отчёты (2–3 строки после каждой фазы).

Б. Новая задача: разовый розыгрыш «Анархия Новой Эры». Hard gate на розыгрыши открывается ТОЛЬКО в этом объёме. Владелец также разрешает деплой ТОЛЬКО мини-выкладки розыгрыша на выделенный сервер (доступ даст владелец: отдельный пользователь без root, ключ вне репозитория, секреты в чат и в логи не выводить), с миграциями только модуля розыгрыша. Остальной production остаётся запрещён. Юридические вопросы, правила и условия берёт на себя владелец, их не продумывай.

Параметры (всё меняется настройкой на сайте, без пересборки; поднимать порог после старта нельзя, только снижать): порог 50 часов; старт 22 ноября, отсечка 30 декабря 23:59:59; часовой пояс Europe/Moscow (допущение). Онлайн считается только на сервере «Анархия Новой Эры» (идентификатор сервера из списка разрешённых на сайте; плагин ставится только на этот сервер, события с других отбрасываются). До старта время не считается. Участие бесплатное, без донат-бонусов. Домен giveaway.twomc.su, логотип ведёт на https://twomc.su.

Билет: одна буква A–Z плюс три цифры (например K417), CSPRNG, уникален, один билет на игрока (UUID), определяется сервером до анимации. Победители определяются НЕ заранее заданными номерами, а розыгрышем среди выданных билетов после отсечки.

ФАЗА 1 (срочно, нужна к 22 ноября): подсчёт времени.
1. Плагин (Spigot API, Universal Spigot 1.21.4–1.21.11, Java 21, только стабильный API, без NMS; Gradle с wrapper; структура как у плагина Bridge, иначе plugins/twomc-giveaway/). Шлёт на сайт подписанные события сессий (вход, выход, пульс раз в минуту), асинхронно, копит события в локальной очереди при недоступности сайта. AFK не считается (порог в конфиге, допущение 5 минут: нет движения и действий). Ключ сервера и адрес API из конфига или окружения, не из репозитория.
2. Бэкенд (модуль giveaway, флаг, миграции expand-only на одноразовой БД): приём событий с подписью HMAC, отметкой времени и одноразовым номером, ключ на сервер, ротация; суммирование времени с учётом перекрытий; настройки розыгрыша (порог, даты, разрешённые серверы). Минимальная выкладка: только модуль розыгрыша, остальное выключено.
3. Деплой на выданный сервер (docker compose, HTTPS, nginx без буферизации для SSE), DNS-запись для giveaway.twomc.su в Beget сделает владелец. Тестовый сервер Minecraft ставь на этот же сервер, не на ПК владельца (диск и ОЗУ ограничены).
4. Проверь режим входа игрового сервера (online-mode или плагин авторизации) и запиши риск подделки ника в QUESTIONS.

ФАЗА 2: билеты.
1. Страница /giveaway в стилистике сайта («Полдень», Lucide, solid-оверлеи, без blur, мобильная и клавиатурная доступность). Кнопка «Получить код»: сайт выдаёт 16-значный код (алфавит Crockford без I, L, O, U, вид XXXX-XXXX-XXXX-XXXX, CSPRNG, хранится только хэш, одноразовый, срок жизни около 10 минут, привязан к сессии браузера, лимиты по IP и IPv6 /64, капча при необходимости, кнопка «Новый код»).
2. В игре команда /giveaway <код> (псевдоним /ticket): плагин спрашивает сайт, набрано ли время (иначе показывает сколько осталось); если набрано, код привязывается к нику и UUID игрока, который ввёл команду. Страница сама обновляется (опрос или SSE) и показывает анимацию «крутятся буквы и цифры» и билет (prefers-reduced-motion учитывать). Повторное обращение показывает уже выданный билет. Ответы не раскрывают существование чужих кодов.
3. Уведомление в игре при достижении порога (чат, заголовок, звук).
4. Панель на экране в красной области над правым блоком (скриншот владельца). Плагин отдаёт данные плейсхолдерами (PlaceholderAPI-расширение: часы, осталось, процент, флаг «набрано»). Найди плагин, который рисует существующие панели (ресурс-пак), и подключи новый блок через него. Если невозможно, подготовь собственный блок (ассеты и инструкция для ресурс-пака, обновление пака делает владелец). Запасной вариант: плагин TAB. Босс-бар и скорборд не использовать.

ФАЗА 3: итоги, админка, эфир.
1. Админка на поддомене, вход через Discord OAuth2 (проверка по allowlist из трёх Discord ID: владелец, разработчик, второй владелец; ID и ключи приложения Discord даст владелец в конфиге, не в репозитории), короткие сессии, аудит. Права: просмотр билетов, настройки, призы, розыгрыш, тестовый режим. Создавать новые розыгрыши в интерфейсе нельзя.
2. Призы: название, количество, PNG-изображение (клавиатура, микрофон и др.). Загрузка PNG только проверенная (сигнатура, размер до 2 МБ, перекодирование), либо файлы в статике.
3. Розыгрыш: после отсечки список билетов замораживается (публикуется хэш снимка). Кнопка «Рассчитать» (подтверждение, необратимо, один раз): CSPRNG-зерно, победители среди выданных билетов, результат сначала виден только в админке (предпросмотр), затем кнопка «Показать в эфире». Публикуются зерно и порядок, чтобы результат можно было проверить.
4. Эфир: при «Показать в эфире» сервер рассылает событие всем открытым страницам (SSE, запасной вариант опрос раз в 5 секунд); публичная страница сама переключается в режим итогов и по очереди показывает победителей с анимацией и картинкой приза. Публично только ник и билет.
5. Тестовый режим (флаг, доступен только админам): отдельный тестовый розыгрыш с изолированными данными, возможность выдать тестовое время нику и провести пробный розыгрыш и эфир без отыгрыша 50 часов. На странице чёткая метка «ТЕСТ». Тест никогда не затрагивает реальные данные, а в реальном розыгрыше ручное начисление времени отключено.

Безопасность: ревью Security один раз по приёму событий, выдаче и погашению кодов, розыгрышу и Discord-входу. Правила main прежние (три зелёные проверки, CLEAN). Ничего не удалять, без force-push, bypass permissions не снимать. Вопросов мне не задавай, допущения записывай в QUESTIONS-FOR-OWNER.md. После каждой фазы отчёт 2–3 строки.

Дополнение владельца (1). Начинай прямо сейчас с того, что не зависит от сервера: плагин, модуль приёма событий и настройки розыгрыша, проверка локально (одноразовая БД, тестовый запуск без выкладки). Привязку к сайту и страницы пока не делай. Сервер владелец купит примерно в 15:00 по МСК и тогда даст доступ, после этого выкладывай мини-версию (Фаза 1). Время: везде хранить в UTC, логику дат (старт, отсечка) считать по Europe/Moscow, на сайте и в плагине показывать «по МСК» с явной подписью часового пояса, чтобы игроки из других поясов не путались.

Дополнение владельца (2). Уточнение владельца по расположению. Создай в корне репозитория папку giveaway/ и держи в ней всё, что относится к розыгрышу и не является кодом сайта: плагин (giveaway/plugin, Gradle с wrapper), конфигурацию мини-выкладки (docker compose, nginx), документы и ADR розыгрыша, PNG призов, инструкции. Код бэкенда и страницы пиши как модуль giveaway внутри apps/api и apps/web, чтобы не дублировать стек, и выключай всё остальное флагом в мини-выкладке. Существующий код не удалять и не переписывать. Добавь в giveaway/ короткий README: что где лежит, как собрать плагин и как запустить.
