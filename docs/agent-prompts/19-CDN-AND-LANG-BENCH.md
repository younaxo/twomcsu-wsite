## Задача 1. CDN и файловое хранилище cdn-files.twomc.su (домен привязан к IP VDS)
1. nginx + HTTPS (certbot); отдельный каталог (квота, бэкап); публике только чтение; без листинга; X-Content-Type-Options: nosniff; без исполнения скриптов; CORS для twomc.su, test-website.twomc.su, giveaway.twomc.su; Cache-Control: public, max-age=31536000, immutable для файлов с хэшем в имени; gzip; webp и avif.
2. Загрузка/управление только через защищённый путь. Медиа-библиотека в админке (загрузка, список, удаление, права): тип по сигнатуре, лимит размера, перекодирование изображений, имена по хэшу содержимого; SVG только очищенные, иначе запрет. Опционально File Browser за basic auth на закрытом пути.
3. Перенос всех картинок сайта на CDN (товары, призы, логотипы, иконки, статика); в коде CDN_BASE_URL (по умолчанию https://cdn-files.twomc.su); скрипт синхронизации одной командой; docs/runbooks/cdn.md. Без приватных файлов, ПДн, секретов.
4. Готовность к Cloudflare позже (стабильные URL, заголовки кеша).

## Задача 2. Эксперимент TypeScript / Rust / Java (разрешён владельцем)
- Всё тяжёлое (сборка, Rust, JDK, бенчмарки) — только на VDS; локально только исходники. Основной код не менять; всё в experiments/lang-bench/.
1. Модуль: расчёт корзины (POST /store/cart/calculate). Три реализации: текущая TS (NestJS), Rust (axum, tokio), Java 21 (виртуальные потоки, лёгкий фреймворк). Одинаковый HTTP-контракт, тестовые данные.
2. Эквивалентность: общие golden JSON-фикстуры, совпадение копейка в копейку (Decimal, без float).
3. Бенчмарк на VDS: отдельные контейнеры с одинаковыми лимитами CPU/памяти, по очереди, прогрев, нагрузки 1/50/500 одновременных, поток ≥ 60 с; k6 или wrk/oha; метрики RPS, p50/p95/p99, CPU, память, холодный старт, размер образа; когда стенд не под нагрузкой, лимиты CPU и nice.
4. Отчёт docs/reports/lang-bench-report.md + короткая сводка владельцу (таблица, выводы, оговорки про БД/сеть, стоит ли переписывать и что). Код и результаты — на стенд за basic auth.
5. Не внедрять в основной сайт без команды владельца.
