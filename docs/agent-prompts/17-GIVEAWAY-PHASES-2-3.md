# 17. Розыгрыш «Анархия Новой Эры» — продолжение (фазы 2–3, выкладка)

Дата: 2026-11-19. Текст владельца дословно.

ПОЛНЫЙ ПРОМПТ ВЛАДЕЛЬЦА: розыгрыш «Анархия Новой Эры», продолжение. Вопросов мне не задавай, сомнения решай безопасным допущением и записывай в QUESTIONS-FOR-OWNER.md. Лимит использования ограничен: один исполнитель, один ревьюер Security на каждую фазу, точечные тесты, короткие отчёты (2–3 строки после каждого шага). Работу над остальным сайтом не вести.

СТАТУС. Фаза 1 (приём времени, плагин, мини-выкладка) слита в main (PR #199–#201), на сервер не выложена. Владелец оплатит VDS, как только придут деньги, и сразу даст доступ. До этого работай ЛОКАЛЬНО: фазы 2 и 3 не зависят от сервера. Проверяй на моках и одноразовой БД, тяжёлые прогоны только при ОЗУ не меньше 2 ГБ (Docker может быть выключен, не включай его без нужды).

ПАРАМЕТРЫ (меняются настройкой на сайте, без пересборки; после старта порог можно только понижать): порог 50 часов; старт 22 ноября, отсечка 30 декабря 23:59:59; логика дат по Europe/Moscow, в базе UTC, на сайте и в плагине подпись «по МСК». Онлайн считается только на «Анархии Новой Эры». Участие бесплатное, без донат-бонусов. Домен giveaway.twomc.su (замени giveaway.example.com везде), логотип ведёт на https://twomc.su. Всё розыгрышное держи в giveaway/ (плагин, deploy, docs, PNG призов), модуль в apps/api и страницы в apps/web как модуль giveaway, всё остальное выключено флагом GIVEAWAY_ONLY. Ничего не удалять, без force-push, bypass permissions не снимать.

ФАЗА 2: билеты (начинай сейчас).
1. Страница /giveaway в стилистике сайта («Полдень», Lucide, solid-оверлеи, без blur, мобильная и клавиатурная доступность). Показывает ход розыгрыша, даты по МСК, порог.
2. Кнопка «Получить код»: сайт выдаёт 16-значный код (алфавит Crockford без I, L, O, U, вид XXXX-XXXX-XXXX-XXXX, CSPRNG, хранится только хэш, одноразовый, срок жизни около 10 минут, привязан к сессии браузера, лимиты по IP и IPv6 /64 и по коду, капча при необходимости, кнопка «Новый код»).
3. Плагин: команда /giveaway <код> (псевдоним /ticket). Плагин спрашивает сайт: набрано ли время (иначе показывает, сколько осталось); если набрано, код привязывается к нику и UUID игрока, который ввёл команду. Страница сама обновляется (опрос или SSE) и показывает анимацию «крутятся буквы и цифры» и билет (prefers-reduced-motion учитывать). Повторное обращение показывает уже выданный билет. Ответы не раскрывают существование чужих кодов.
4. Билет: буква A–Z (допущение: без I и O) плюс три цифры, например K417; CSPRNG, уникален (ограничение уникальности и повтор при коллизии), один билет на игрока (UUID), определяется сервером ДО анимации.
5. Уведомление в игре при достижении порога (чат, заголовок, звук).
6. Панель на экране в красной области над правым блоком (скриншот владельца). Плагин отдаёт данные плейсхолдерами (PlaceholderAPI-расширение: часы, осталось, процент, флаг «набрано»). Найди плагин, который рисует существующие панели (ресурс-пак), и подключи новый блок через него. Если невозможно, подготовь собственный блок (ассеты и инструкция для ресурс-пака, обновление пака делает владелец). Запасной вариант: плагин TAB. Босс-бар и скорборд не использовать.

ФАЗА 3: итоги, админка, эфир.
1. Админка на поддомене, вход через Discord OAuth2 (allowlist из трёх Discord ID: владелец, разработчик, второй владелец; ID и ключи приложения Discord даст владелец в конфиге, не в репозитории), короткие сессии, аудит. Права: просмотр билетов, настройки, призы, розыгрыш, тестовый режим. Создавать новые розыгрыши в интерфейсе нельзя.
2. Призы: название, количество, PNG-изображение (клавиатура, микрофон и др.; PNG пришлёт владелец). Загрузка PNG только проверенная (сигнатура, размер до 2 МБ, перекодирование), либо файлы в статике.
3. Розыгрыш: после отсечки список билетов замораживается (публикуется хэш снимка). Победители НЕ заданы заранее, а выбираются среди выданных билетов. Кнопка «Рассчитать» (подтверждение, необратимо, один раз): CSPRNG-зерно, результат сначала виден только в админке (предпросмотр), затем «Показать в эфире». Публикуются зерно и порядок, чтобы результат можно было проверить. До выдачи призов владелец проверяет победителей вручную (аномалии онлайна, накрутка), поэтому в админке покажи по каждому победителю суммарное время и профиль онлайна по дням и дай возможность отметить «дисквалифицирован» с переопределением (повторный выбор нового победителя для этого места по тому же зерну и правилу).
4. Эфир: при «Показать в эфире» сервер рассылает событие всем открытым страницам (SSE, запасной вариант опрос раз в 5 секунд), публичная страница сама переключается в режим итогов и по очереди показывает победителей с анимацией и картинкой приза. Публично только ник и билет.
5. Тестовый режим (флаг, доступен только админам): отдельный тестовый розыгрыш с изолированными данными, возможность выдать тестовое время нику и провести пробный розыгрыш и эфир без отыгрыша 50 часов. На странице чёткая метка «ТЕСТ». Тест никогда не затрагивает реальные данные, а в реальном розыгрыше ручное начисление времени отключено.

ВЫКЛАДКА (после выдачи доступа). Владелец оплатит VDS и даст доступ: отдельный пользователь без root, ключ вне репозитория, секреты в чат и логи не выводить. Разрешены: деплой ТОЛЬКО мини-выкладки розыгрыша и миграции только модуля розыгрыша. Порядок: сначала выложить фазу 1 (до 22 ноября), поставить тестовый Minecraft-сервер на этот же VDS и проверить плагин на 1.21.4 и 1.21.11 (вход, выход, подсчёт, AFK, обрыв связи с сайтом, перезапуск), затем выкладывать фазы 2 и 3 по мере готовности. GIVEAWAY_MASTER_SECRET сгенерируй сам на сервере (openssl rand -hex 32, запись сразу в файл окружения с правами 600), в вывод не печатай. DNS-запись giveaway в Beget, приложение Discord и PNG призов даст владелец. Проверь синхронизацию времени (timedatectl) на новом сервере.

БЕЗОПАСНОСТЬ И ПУБЛИКАЦИЯ. Ревью Security один раз на фазу 2 (выдача и погашение кодов) и один раз на фазу 3 (Discord-вход, розыгрыш, эфир, тестовый режим). Правила main прежние: PR, три зелёные проверки, CLEAN. Допущения (Q88 online-mode, AFK, несколько аккаунтов) оставь в QUESTIONS.

ПОРЯДОК: ADR фазы 2 → бэкенд → плагин → страница → ревью → PR → ADR фазы 3 → бэкенд → админка → эфир и тестовый режим → ревью → PR. После каждого шага отчёт 2–3 строки.
