# Level System — требования владельца (FUTURE / NOT STARTED)

Зафиксировано 2026-10-10. Этап **не начат** и запускается только по отдельной команде
владельца. Здесь — требования и найденные ассеты, чтобы их не потерять.

## Прогрессия

- Уровни **1 → 70**, затем **один финальный TwoMC badge** — и прогрессия заканчивается.
- Финальный badge — **не Level 71**: публично это «70 уровней + 1 знак завершённой
  прогрессии». Никаких Level 71 / 80 / 100, prestige, rebirth, reset, бесконечных циклов.
- После финала — completed state («MAX» или «Прогресс уровней завершён» + финальный badge),
  без «0 / 999999 XP до Level 71» и «Следующий уровень: 71».
- Если gameplay продолжает считать активность, она не создаёт новые уровни; lifetime-статистика
  (если появится) — отдельно от шкалы прогресса.
- Переход 70 → финал решить до реализации (A: достижение 70 сразу даёт badge; B: у 70 своя
  шкала XP, badge — после её заполнения) и зафиксировать в ADR, без off-by-one.

## Архитектура

- Backend — source of truth: `currentLevel`, `currentXp`, `xpForCurrentLevel`, `xpForNextLevel`,
  `progressPercent`, `maxProgressReached`, `finalBadgeUnlocked` (или эквивалент). Frontend не
  решает сам, повысился ли уровень.
- Центральный реестр ассетов (`getLevelIcon(level)` или эквивалент) — без 70 условий и без CDN
  URL в компонентах.
- Level ≠ prefix: не заменяет STAFF / MEDIA / DONATION префиксы, может стоять рядом.
- Level ≠ Donation (Dionysus … Zeus) и ≠ Staff RBAC: уровень не даёт прав и привилегий.
- Награды за milestone-уровни (10, 25, 50, 70, финал) — только через существующий модуль
  наград и значков, без выдуманных наград заранее.

## Где показывать

Public Profile, Mini Profile, Player Card, Leaderboards, Friends, Chat (если не перегружает),
страница прогресса, admin-просмотр пользователя. Размер — по контексту, без огромной иконки у
ника. Тултип — production Tooltip («Уровень 37», «Прогресс уровней завершён»), не `title=""`.
