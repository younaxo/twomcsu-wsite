# Демо-данные для локальной разработки

Сценарий `apps/api/prisma/seed/demo/` наполняет локальную БД витриной: магазин (14 товаров), новости, правила/FAQ/информация, события, формы с заявками, серверы, наказания, достижения, голосование. Обычный `prisma db seed` демо-данные НЕ создаёт.

## Защита запуска (fail closed)

Сид завершается с ошибкой (код != 0), если не выполнено всё сразу:

- `NODE_ENV=development` (пустой или незаданный = production, отказ);
- `SEED_DEMO=1`;
- `DATABASE_URL` указывает на `localhost` или `127.0.0.1`.

Никогда не запускайте на production и на общей dev-БД.

## Поднять локально

Команды только как справка; БД должна быть одноразовой (порт и пароль свои):

```sh
docker run --name twomc-demo-pg -e POSTGRES_PASSWORD=<пароль> -e POSTGRES_DB=twomc -p 5432:5432 -d postgres:16
docker run --name twomc-demo-redis -p 6379:6379 -d redis:7
```

В корневом `.env` (создаёт разработчик, в репозиторий не коммитится) задайте `DATABASE_URL` на `localhost`.

## Запуск

```sh
pnpm --filter api db:migrate        # или db:deploy: схема в одноразовой БД
pnpm --filter api db:seed           # роли, права, bootstrap-аккаунты (нужен автор новостей и форм)
SEED_DEMO=1 NODE_ENV=development pnpm --filter api db:seed:demo
```

Повторный запуск безопасен (upsert по slug и ключам). Удалить одноразовую БД: `docker rm -f twomc-demo-pg twomc-demo-redis`.

## Что внутри и допущения

- Привилегии: цена «от» = вариант на 1 месяц (Полемизм 1499, Сварог 799, Кратос 599, Аполон 399, Деймос 299, Арес 129, Гефест 39). Допущение: 3 месяца = x2.5, навсегда = x8.
- Кейсы (Донат 89, Титульный 19, Рубиновый 79), Размут 89, Разбан 199, Боевой пропуск премиум 299 (вариант SEASON), Рубины 1 руб за единицу (`maxPerPurchase` 100000).
- Команды выдачи — шаблоны `{username}` в `Product.gameCommands`; реальные команды сервера уточняются при подключении.
- Наказания: 7 записей в зеркале (`source=litebans`, `sourceScope=default`, id со сдвигом 900000000, чтобы список /punishments/public читал их), без IP и контактов, выдавший скрыт (`issuerHidden`). Флаг `punishments.public.enabled=true` и `PunishmentSyncState` (initialSyncDoneAt по всем видам) ставятся только этим сидом; `LITEBANS_ENABLED` не трогается. Если включить реальную синхронизацию LiteBans, она может пометить демо-строки удалёнными: это только dev.
- Контент страниц /rules, /faq, /info, /events: 9 тем `Topic` (3 RULES, 4 FAQ, 2 INFORMATION; slug `demo-rule-*`, `demo-faq-*`, `demo-info-*`; visibility PUBLIC, isActive) и 2 `CalendarEvent` (slug `demo-event-upcoming` — PUBLISHED, +7 дней от запуска; `demo-event-past` — тоже PUBLISHED, но старт и окончание в прошлом (−14 дней): публичная выдача показывает только PUBLISHED, статус COMPLETED скрыл бы событие; запись на него API запрещает (403 «Событие уже прошло»), web показывает «Событие уже прошло»; visibility PUBLIC). Все заголовки с префиксом «[Демо]», в темах фраза «Демонстрационный текст для тестового стенда; настоящие правила утверждает администрация.», в событиях — «Демонстрационное событие для тестового стенда.»; без санкций, цен и ПДн. Автор — отдельный пользователь `demo_system` (см. ниже). Upsert по slug: повторный запуск не дублирует, но пересчитывает даты событий от текущего момента.
- Соцданные (срез B): 6 вымышленных игроков `demo_ember`, `demo_frost`, `demo_gale`, `demo_ivy`, `demo_onyx`, `demo_pixel` (email `demo-*@example.invalid`, tag `demo_x#0000`, без ролей и 2FA, пароль не bcrypt-хеш, вход невозможен; создаются upsert-ом по username; если пользователь с таким username уже есть и его email не демо-шный, сид прерывается с ошибкой до любых записей и ничего не меняет; у существующего демо-пользователя email и пароль не перезаписываются). Для каждого: `PlayerStatistics` (монеты, время, убийства/смерти/удары, K/D), снимки `PlayerInventory` на сервере `anarchy-new-era` (группы main и ender, хотбар и Ender Chest, ванильные предметы; контрольная сумма как в API; `InventoryPrivacy` не создаётся, значит инвентарь приватен). 6 дружб между демо-игроками (5 принятых, 1 входящая заявка `demo_pixel` -> `demo_ember`), 2 беседы (ЛС `demo_ember` и `demo_frost`; группа «[Демо] Команда стенда», 4 участника, владелец `demo_onyx`), 5 комментариев профиля (один ответ). Тексты с префиксом «[Демо]»; id бесед, сообщений и комментариев стабильные (`demo-conv-*`, `demo-dm-*`, `demo-gm-*`, `demo-pc-*`), повторный запуск не дублирует, время сообщений и снимков пересчитывается от текущего момента. Запускать только на одноразовой БД.
- Настройки стенда (`SiteSetting`, upsert): `punishments.public.enabled`, `stats.public.enabled` и `store.delivery.enabled` = `true`; исполнители выдачи `store.delivery.executor.command.enabled` и `store.delivery.executor.bridge.enabled` ЯВНО `false` (заказы не уходят на игровой сервер, Bridge не нужен). `punishments.paidRemoval` НЕ задаётся: правилам нужен `actorUserId` системной учётной записи, которую создаёт владелец.
- «Мои наказания» и обжалования (демо-игрок `demo_ember`): ему привязан фиктивный `MinecraftAccount` (ник `DemoEmber`, uuid `de30c0de-0000-4000-8000-00000000e4b3`, версия 4; офлайн-версия 3 сайт считает «нет привязки»). Три наказания зеркала с `subjectUuid` этого аккаунта: BAN активный (9001), MUTE истёкший (9007), WARN истёкший (9003). Два обращения `PUNISHMENT_APPEAL` на BAN 9001: `R-DEMO-APPEAL-1` (REJECTED, с вердиктом) и `R-DEMO-APPEAL-2` (IN_REVIEW). Всё через upsert (повтор не дублирует). Смотреть: страница `/settings/punishments` под `demo_ember`. Пароля у demo_* нет (вход по сидированному паролю невозможен, см. выше), поэтому на стенде вход под `demo_ember` делает владелец тем же способом, каким он ведёт остальные demo_* (например, задаёт пароль в БД стенда сам); сид пароль не создаёт и не публикует.
- Пропущено (нет модели): разделы правил, рейтинги. Платежи: сид ничего не создаёт, используется mock-провайдер без ключей.
- Автор новостей, форм, тем и событий — отдельный пользователь `demo_system` (email demo-system@example.invalid, без ролей, пароль не является bcrypt-хешем, вход невозможен; создаётся upsert-ом по username (чужой demo_system с другим email — сид прерывается без изменений), позиция — по умолчанию из обычного `db:seed`). Реальные пользователи в публичные ответы (организатор события) не попадают.
- Демо-сайт голосования заведён с невалидным хешем секрета (вебхук не принимается).

## Перед включением реальной синхронизации LiteBans в dev

Демо-сид заранее выставляет PunishmentSyncState.initialSyncDoneAt, поэтому реальная синхронизация пропустит первичную загрузку и пойдёт в режиме опроса (возможна сверка по откату курсора). Перед включением LITEBANS_ENABLED в dev очистите таблицу PunishmentSyncState и демо-строки наказаний с sourceId ≥ 900000000 (только в локальной одноразовой БД). Старые демо-строки с source=demo из прошлых запусков в публичном списке не видны и остаются в dev-БД как мусор.
