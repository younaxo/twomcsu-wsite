# Runbook: смоук-тест после выкладки

Актуализировано 2026-11-28 (способ оплаты, обжалование, рейтинги, инвентарь, admin delivery, realtime). Ручные шаги после `infrastructure/deploy.sh` (автоматизации деплоя нет, скрипты не добавлялись). Выполняет владелец или назначенный им человек; тестовые данные не должны включать реальные ПДн и секреты в отчёте. Приёмка целиком - `acceptance-checklist.md`.
Критерий: все шаги выполнены без ошибок; при провале - `deploy.md` («Откат образов»), для оплаты - `payments.md`, раздел 4.

## 1. Инфраструктура (на сервере)

1. `docker compose --env-file .env -f infrastructure/docker-compose.prod.yml ps`: postgres, redis healthy; api и web running, без рестартов.
2. `curl -fsS -m 5 http://127.0.0.1:4000/health` возвращает `{"status":"ok","database":"ok"}`; `curl -fsS -m 5 http://127.0.0.1:3000/` - 200.
3. `docker compose ... logs --tail=200 api`: есть строка «Prisma подключён к базе данных (транзакции: maxWait ..., timeout ...)», нет ошибок старта и «Не удалось отправить уведомление».
4. `cat .release` совпадает с `git rev-parse --short HEAD`.
5. Снаружи: `https://twomc.su/` открывается по HTTPS без предупреждений; API по HTTPS отвечает на `/health`.

## 2. Сайт и вход

1. Главная, каталог и страница товара открываются, нет ошибок в консоли браузера.
2. Регистрация или вход тестовым аккаунтом (Turnstile проходит), выход.
3. Вход сотрудника с 2FA; действие по праву, требующее 2FA, не даёт 403 `admin_2fa_required`.
4. Загрузка изображения (проверка `uploads`).
5. Реальный IP клиента виден в аудите/логах, а не адрес прокси (`TRUST_PROXY=1`, `cloudflare-real-ip.md`).
6. Realtime: после входа открыть страницу с уведомлениями или чатом; в DevTools (Network, WS) соединение socket.io устанавливается (101), по пути выбранного варианта: `/socket.io` при API на поддомене, `/api/socket.io` при API под префиксом; нет цикла переподключений и сообщения «нет связи». Нарушенный путь или отсутствие `Upgrade` в nginx - частая причина.
7. Cookie 2FA: вход сотрудника с 2FA проходит шаг подтверждения (при API под префиксом нужен `proxy_cookie_path /auth /api/auth`, `test-website-stand.md`, раздел 8).
8. Статика: `curl -sI https://cdn-files.twomc.su/health.txt` - 200 и `X-Content-Type-Options: nosniff`; картинки сайта грузятся с CDN без ошибок CORS (`cdn.md`).

## 3. Оплата (только если включена; иначе проверить отказ)

Оплата выключена (`PAYMENT_PROVIDER` и `PAYMENT_METHODS` пусто): `GET /store/payment-methods` возвращает пустой список, оформление заказа отвечает 503 `payment_unavailable` (в том числе quick-buy), интерфейс не ломается и не показывает сырой текст ошибки.
Оплата включена:

1. Страница оформления показывает доступные способы оплаты (`GET /store/payment-methods`, названия без имени провайдера). Без выбора способа запрос отвечает 400 `payment_method_required`, неизвестный способ - 400 `payment_method_invalid`, выключенный - 400 `payment_method_unavailable`; заказ при этом в БД не создаётся.
2. Оформление недорогого товара выбранным способом, переход на страницу провайдера, оплата малой суммы; в заказе сохранены способ и провайдер.
3. Вебхук принят: заказ в админке `COMPLETED`; в логе api нет 401 по вебхуку.
4. Неподписанный запрос `POST /webhooks/payments/<провайдер>` даёт 401 (без тела с реальными данными); вебхук чужого провайдера по заказу отклоняется (`provider_mismatch`).
5. Повторная доставка вебхука (из кабинета провайдера) не создаёт второго завершения и дубля заданий выдачи.

## 4. Выдача и админка выдачи

Если `STORE_DELIVERY_ENABLED`/`store.delivery.enabled` выключены: задания создаются, но не выполняются (ожидаемо).
Админка выдачи (право `store.delivery.view`): `/admin/delivery/tasks` открывается, у роли без права - 403; список показывает статусы `PENDING`, `DELIVERED`, `NEEDS_ATTENTION`, `AWAITING_MANUAL` и т. д.; `manual-done` и `retry` доступны только с `store.delivery.manage`.
Если Bridge выключен (`BRIDGE_ENABLED` не `true` или `BRIDGE_DELIVERY_ENABLED` не `true`): задания идут исполнителям `command`/`manual`, запросы `/bridge/v1/delivery/*` отвечают отказом (503/403), раздел инвентаря показывает «Инвентарь скоро появится» (503 `inventory_unavailable` в API) - это штатно.
Если Bridge-выдача включена (только после M раздела приёмки): заказ тестового игрока на тестовом игровом сервере - задание `DELIVERED`, команда выполнена один раз; повторный ack того же задания не дублирует выдачу; `/twomcbridge status` без ошибок; `UNKNOWN` (если случился) виден в админке и не повторяется сам.
Если включены: задание выдачи выполнено, привилегия/команда видна в игре под ником тестового игрока; при сбое сервера игры задание не теряется (статус виден в админке).

## 5. Возврат (если `STORE_REFUNDS_ENABLED=true`)

1. `GET /admin/store/refunds` открывается у роли с `orders.refund`, у роли без права - 403.
2. Возврат тестового заказа с TOTP и причиной: `REFUNDED`, повтор того же запроса даёт 409 (`order_already_refunded` или `refund_in_progress`).
3. Для выданного товара обычный возврат даёт 409 `refund_after_delivery`; override доступен только владельцу.
При выключенном флаге: `GET /admin/store/refunds` даёт 503 `refunds_disabled`.

## 6. Quick-buy (если `QUICK_BUY_ENABLED=true`)

Оформление по нику без входа проходит; 11-й запрос за минуту с одного IP получает 429; при выключенном флаге оформление отвечает отказом `QUICK_BUY_DISABLED`.

## 7. Обжалование наказания (при включённом зеркале LiteBans)

1. `/punishments/me` у игрока с привязанным аккаунтом показывает наказание с `appealable`; без привязки - 403 `minecraft_not_linked`.
2. Подача обжалования: обращение создаётся, статус виден игроку (`appeals[]`: номер, статус, даты); повторная подача по тому же наказанию - 409 `appeal_already_open`; после закрытия - 429 `appeal_cooldown` (24 ч).
3. Чужое или несуществующее наказание - 404; в обращении у персонала нет IP, причины и uuid выдавшего.
4. Решение по обращению не меняет запись в LiteBans.

## 8. Статистика и рейтинги

1. При выключенной настройке `stats.public.enabled` `GET /leaderboards` отдаёт пустые списки, страница показывает «Скоро».
2. После включения: рейтинг показывает только открытые профили без `hideStatistics`; закрытый профиль - `hidden: true`; блок «Покупки» скрыт до запуска оплаты; лимит 60/мин на `GET /leaderboards` даёт 429.
3. Допущение: бан кэш рейтинга может не сбросить до 30 с (Q109).

## 9. Инвентарь

При выключенном `BRIDGE_ENABLED`: `/settings/inventory` показывает «Инвентарь скоро появится». При включённом: страница показывает снимок после того, как игровой сервер прислал данные; чужой инвентарь не виден без решения владельца (Q39).

## 10. Фоновое и эксплуатация

1. В течение 10 минут нет всплеска 5xx и 503 `busy`.
2. Бэкап: `BACKUP_TAG=smoke infrastructure/backup/backup.sh` завершается кодом 0 (метка не `scheduled`, чтобы не сокращать глубину ежедневных копий).
3. Свободное место (`df -h`) в норме.
4. Результат смоука записан владельцем (дата, sha релиза, отметка по разделам).
