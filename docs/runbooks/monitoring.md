# Runbook: мониторинг и алерты (минимум без платных сервисов)

Платные API и сервисы мониторинга - hard gate владельца: ниже только то, что работает на сервере бесплатно (cron, `curl`, `docker`, `psql`, логи). Сервера пока нет (R8): расписания и уведомления не настроены, раздел описывает, что настроить владельцу. Агенты на production не ходят.

## 1. Что мониторить

| Что                                  | Как проверить                                                                                                         | Порог/алерт                                                  | Если сработало                                       |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------- |
| Health API                           | `curl -fsS -m 5 http://127.0.0.1:4000/health` (ответ `{"status":"ok","database":"ok"}`; недоступна БД - 503)        | любой не-200 два раза подряд                                 | логи api, `docker compose ... ps`, раздел «Откат»    |
| Web                                  | `curl -fsS -m 5 http://127.0.0.1:3000/`                                                                               | не-200 два раза подряд                                       | логи web                                             |
| Внешняя доступность                  | `curl -fsS -m 10 https://twomc.su/` и `https://<API>/health` с другой машины (бесплатный внешний пинг по желанию владельца) | недоступно 3 минуты                                          | nginx, DNS/Cloudflare, сертификат                    |
| Ошибки 5xx                           | `docker compose ... logs --since 15m api \| grep -c ' 5[0-9][0-9] '` (формат подгонять под фактический лог) и лог nginx | устойчивый рост; 503 `busy` - исчерпан пул БД (ADR-0183)     | `production-env-checklist.md`, раздел «Пул»          |
| Очередь заданий выдачи               | SQL по таблице заданий выдачи (имя сверить с `apps/api/prisma/schema.prisma`): число в `PENDING`/`IN_PROGRESS`/`FAILED` старше N минут | задания FAILED > 0 или PENDING старше 15 минут               | админка заказов, ручная отметка, логи сервера игры   |
| Сверка платежей и возвратов          | Заказы в `PENDING` оплаты старше 1 часа; заказы в `REFUND_PENDING` и `REFUND_FAILED`; лог сверки (id заказов и коды) | любой `REFUND_FAILED`; `REFUND_PENDING` старше 24 часов      | `docs/runbooks/payments.md`, раздел 5                |
| Всплеск 401 на вебхуке               | Лог api: ответы 401 на `/webhooks/payments/`                                                                          | более 10 за 10 минут                                         | `payments.md`, п. 5.4                                |
| Бэкапы                               | Код выхода `backup.sh` (0/1/3/4/5, `backup-restore.md`); возраст свежего каталога в `BACKUP_DIR`                      | ненулевой код; свежий бэкап старше 26 часов                  | `backup-restore.md`                                  |
| Копия бэкапа вне сервера             | Дата последней вывезенной копии (вручную)                                                                             | старше 7 суток                                               | вывезти                                              |
| Место на диске                       | `df -h /` и `docker system df`                                                                                        | занято более 80%; менее `BACKUP_MIN_FREE_MB` (2048) для бэкапа | чистка вручную (`docker builder prune` осознанно)    |
| Память Redis                         | `redis-cli -a "$REDIS_PASSWORD" info memory` внутри контейнера                                                        | `used_memory` более ~80% от `REDIS_MAXMEMORY` (192mb); политика `noeviction` | рост памяти = ошибки записи, вход и права 500 |
| Соединения БД                        | `SELECT count(*) FROM pg_stat_activity WHERE datname = current_database();`                                           | постоянно близко к `connection_limit` (15) + служебные       | пересмотр ADR-0183 нагрузкой                         |
| Контейнеры                           | `docker compose --env-file .env -f infrastructure/docker-compose.prod.yml ps`                                         | любой контейнер не `running`/`healthy`, частые рестарты      | логи, откат                                          |
| Сертификат HTTPS                     | `echo \| openssl s_client -servername twomc.su -connect twomc.su:443 2>/dev/null \| openssl x509 -noout -enddate`    | осталось менее 14 дней                                       | продлить; проверить автопродление                    |
| 2FA и аварийный доступ               | раз в квартал: у каждого сотрудника есть резервные коды                                                               | напоминание                                                  | `owner-emergency-access.md`                          |

Примечание: имена таблиц и точные форматы логов в запросах выше нужно сверить на сервере; в репозитории готовых скриптов мониторинга нет (пробел, не реализовано).

## 2. Минимальные средства без платных сервисов

- Cron на сервере раз в минуту/5 минут: скрипт с `curl -fsS` на health api и web, при провале - уведомление бесплатным каналом (письмо через почтовый релей владельца или бот в Telegram; создание бота и токена - решение владельца, агент токены не создаёт).
- Cron раз в сутки: проверка возраста бэкапа и `df -h`, ненулевой код `backup.sh` - уведомление.
- Раз в 5-15 минут: `psql`-запрос по заказам `REFUND_FAILED`, `REFUND_PENDING` старше порога и заданиям выдачи в сбое, при ненулевом числе - уведомление.
- Логи контейнеров ротируются (`LOG_MAX_SIZE` 10m x `LOG_MAX_FILE` 5, `deploy.md`); для 5xx и 401 достаточно `docker compose logs --since`.
- Внешний пинг с бесплатным тарифом (если владелец решит) - только как дополнение: сервис видит внешнюю доступность, но не очереди.
- В коде есть уведомление HIGH персоналу при позднем платеже по `CANCELLED` заказу (ADR-0187); других автоматических алертов нет.

## 3. Реакция

Критично (оплата, выдача, health): сразу выключить затронутое флагом (`payments.md`, раздел 4), затем разбираться. Некритично (диск, сертификат, место для бэкапа): в тот же день. Все инциденты записывать с временем и номерами заказов, без ПДн и секретов.
