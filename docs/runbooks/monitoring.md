# Runbook: мониторинг и алерты (минимум без платных сервисов)

Платные API и сервисы мониторинга - hard gate владельца: ниже только то, что работает на сервере бесплатно (cron, `curl`, `docker`, `psql`, логи). Сервера пока нет (R8): расписания и уведомления не настроены, раздел описывает, что настроить владельцу. Агенты на production не ходят.

### Подробности по очередям выдачи (раздел «Реакция» для выдачи)

- `UNKNOWN` в `bridge_delivery_jobs` и `NEEDS_ATTENTION` в `delivery_tasks` - повод человеку: игрок мог получить или не получить товар. Порядок: проверить в игре (инвентарь, права, баланс), затем либо `manual-done` (товар выдан), либо `/twomcbridge forget <ключ>` на сервере и `retry` в админке (товар не выдан). Не повторять вслепую: админский повтор переиспользует ключ, защита от двойной выдачи только в журнале плагина.
- Retention закрытых заданий Bridge: по умолчанию 30 суток, минимум 14 (`BRIDGE_DELIVERY_JOB_RETENTION_DAYS`); спорную выдачу разбирать до истечения срока.
- Без игрового сервера (Bridge выкл.) очередь `delivery_tasks` наполняется заданиями `manual`: это штатно, смотреть `AWAITING_MANUAL`.

## 2. Минимальные средства без платных сервисов

- Cron на сервере раз в минуту/5 минут: скрипт с `curl -fsS` на health api и web, при провале - уведомление бесплатным каналом (письмо через почтовый релей владельца или бот в Telegram; создание бота и токена - решение владельца, агент токены не создаёт).
- Cron раз в сутки: проверка возраста бэкапа и `df -h`, ненулевой код `backup.sh` - уведомление.
- Раз в 5-15 минут: `psql`-запрос по заказам `REFUND_FAILED`, `REFUND_PENDING` старше порога, заданиям выдачи `NEEDS_ATTENTION`/`FAILED` и заданиям Bridge `UNKNOWN`, при ненулевом числе - уведомление.
- Логи контейнеров ротируются (`LOG_MAX_SIZE` 10m x `LOG_MAX_FILE` 5, `deploy.md`); для 5xx и 401 достаточно `docker compose logs --since`.
- Внешний пинг с бесплатным тарифом (если владелец решит) - только как дополнение: сервис видит внешнюю доступность, но не очереди.
- В коде есть уведомление HIGH персоналу при позднем платеже по `CANCELLED` заказу (ADR-0187); других автоматических алертов нет.

## 3. Реакция

Критично (оплата, выдача, health): сразу выключить затронутое флагом (`payments.md`, раздел 4; флаги слоя 0-1 - `deploy.md`, «Откат: флаги слоя 0-1»), затем разбираться. Некритично (диск, сертификат, место для бэкапа): в тот же день. Все инциденты записывать с временем и номерами заказов, без ПДн и секретов.
