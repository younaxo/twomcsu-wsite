# Implementation tracking — twomc.su

Эта директория — рабочий журнал реализации нового проекта twomc.su. Она отвечает
на три вопроса: что сделано (`STATUS.md`, `CHANGELOG.md`), что ещё предстоит
(`ROADMAP.md`), и почему были приняты те или иные архитектурные решения
(`DECISIONS.md`, `RISKS.md`).

## Файлы

| Файл | Назначение |
|---|---|
| `ROADMAP.md` | Полный список фаз проекта и их статус (`[ ]` / `[x]`) |
| `STATUS.md` | Текущее состояние: активная фаза, ветка, блокеры, результаты проверок |
| `CHANGELOG.md` | Факт реализованных функций (только то, что реально сделано) |
| `DECISIONS.md` | ADR — архитектурные решения и их обоснование |
| `RISKS.md` | Внешние блокеры, ограничения инфраструктуры, отложенные интеграции |
| `COVERAGE.md` | Сверка нового проекта со старой технической документацией |
| `phases/` | По одному файлу на фазу с деталями реализации |

## Источники истины

Приоритет источников при проектировании (см. `DECISIONS.md`, ADR-0001):

1. `MASTER PROMPT` (исходное задание);
2. `docs/technical/` — техпаспорт **старого** проекта (реверс-инжиниринг кода), это
   справочник по бизнес-логике и фактическому поведению, а не цель для копирования;
3. `docs/technical/44-TARGET-ARCHITECTURE.md` — целевая архитектура (приоритетнее
   текущей реализации старого проекта при противоречиях);
4. `docs/technical/45-MIGRATION-PLAN.md`, `10-RBAC-PERMISSIONS.md` (часть B),
   `11-PERMISSION-MATRIX.md` — основа для RBAC нового проекта;
5. остальные документы `docs/technical/*`.

Новый проект **не копирует** старую кодовую базу: технический долг и security-находки
из `42-TECH-DEBT.md` / `29-SECURITY.md` сознательно не переносятся.
