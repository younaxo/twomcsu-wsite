## 9. Исправления по ревью

Ночной режим, владелец не опрашивался; неоднозначности помечены «Допущение».

- M1 (маркеры): `.release` и `.release.prev` пишутся только после успешного health (`write_release_markers`, запись через tmp и mv с проверкой). Автооткат во время деплоя возвращает прежний `.release` и маркеры не трогает. Повторный деплой того же sha оставляет `.release.prev` прежним. Стаб: оба релиза нездоровы, до исправления `.release=new1234`, после `.release=old5678`; повторный деплой new1234, до `.release.prev=new1234`, после `old5678`.
- M2 (`PREDEPLOY_BACKUP_KEEP`): целое не меньше 1, иначе exit 1 до снимка. Свежий снимок исключён из ротации явно. Стаб: значение 0 при двух старых снимках, до исправления удалены все включая свежий, после exit 1, снимки целы, миграции не вызывались; значения abc и -1 дают exit 1; значение 1 оставляет только свежий; значение 2 оставляет свежий и один старый.
- M5 (ADR-0158): обоснование переписано. Prisma не сверяет схему при старте, `/health` делает только `SELECT 1`, порядок держится на expand/contract; отступление от «миграция после health-check» отмечено явно, вопрос владельцу сформулирован в ADR.
- Pre-flight: health текущего релиза до снимка; провал даёт exit 1 без снимка; обход `SKIP_PREFLIGHT=1` с предупреждением. Допущение: 3 попытки (`PREFLIGHT_TRIES`), чтобы не ждать минуты; без `.release` проверка пропускается.
- Деструктивные миграции: скан `migration.sql` между `.release` и `HEAD` (оператор за оператором, без комментариев) на DROP TABLE/COLUMN, RENAME, ALTER COLUMN TYPE, TRUNCATE; найдено или коммит неизвестен git, exit 1 (fail closed); обход `ALLOW_DESTRUCTIVE_MIGRATION=1`. Это эвристика: не ловит `NOT NULL` без default и семантическую несовместимость; ложные срабатывания возможны (слово RENAME в данных миграции). Колонка с именем `type`, `CREATE TYPE` и комментарии не срабатывают.
- Low: `grep -v` в `prune_old_tags` обёрнут в `{ ...; || true; }` (до исправления при отсутствии подходящих тегов успешный деплой завершался exit 1 из-за pipefail); каталог снимков создаётся под `umask 077` (стаб: до `0022`, после `0077`); в `rollback_release` `mv`, чтение и запись файлов проверяются, ложного «выполнен» нет; в `.gitignore` уже есть `.release*` (покрывает `.release.tmp`), изменение не потребовалось.
- Redis: добавлены `--maxmemory ${REDIS_MAXMEMORY:-192mb}` и `--maxmemory-policy noeviction`. Обоснование: в Redis счётчики throttle, вытеснение ослабило бы лимиты; без maxmemory процесс убивается по OOM cgroup (256m) и перезапускается. Риск: при заполнении записи вернут ошибку, поведение API при этом не проверялось (запрещено читать apps). `docker compose config -q` с dummy env: exit 0.
- Регрессия (стабы, exit code): health нового релиза падает, откат на прежний, exit 1; первый деплой с падением health, «Откат невозможен», exit 1; ручной rollback без `.release.prev`, exit 1; с `.release.prev`, exit 0 и `.release=older00`; провал pg_dump, exit 1, миграции не вызывались; обычный успех сдвигает маркеры (exit 0). Проверки sha256 (exit 2), нехватки места (exit 3) и работы без S3 (exit 0) относятся к скриптам бэкапа, а не к deploy.sh: здесь не запускались.
- Не выполнено: реальный запуск, docker build/pull, режим 600 снимка и umask на NTFS (проверить на Linux-сервере).
- Скрипты и вывод: `scratchpad/p3-03a-fix/` (h.sh, scen.sh, before.txt, after.txt).

## 10. Исправления по ревью C

- M-1 (Redis и throttler): в ADR-0158 и runbook исправлено: throttler хранит счётчики в памяти процесса API (`ThrottlerModule.forRoot` без storage, `apps/api/src/app.module.ts:54`), не в Redis; в Redis лежат счётчики brute-force, кеш прав, состояния 2FA и чат. `noeviction` — fail-closed: при заполнении запись падает, вход и проверка прав отвечают 500, обхода лимитов нет, возможен DoS.
