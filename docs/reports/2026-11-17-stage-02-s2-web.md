# Этап 02, срез 2: фронтенд /bans и «Наказания на серверах» (2026-11-17)

Ветка `feature/stage-02-s2-bans-web` (от 675c0a1). Режим: владелец отсутствует. Источник истины: `docs/stage-02/BANS-API-CONTRACT.md` с поправками раунда исправлений (4.2, 6.1: ETag снят с ошибок, `/me` и `admin/*`; `issuer-hidden` требует `punishments.issuer.hide` и `users.punishments`). Типы `packages/shared/src/api/punishments.ts` не менялись.

## Что сделано

1. Публичная страница `/bans` (без входа): таблица банов и мутов (ник, тип, статус, причина, срок, выдавший, область, дата), поиск по префиксу ника (3-16, по кнопке «Найти»), фильтры «Тип» и «Статус», сортировка по дате (заголовок колонки с `aria-sort`), курсорная пагинация «Показать ещё». Карточка `/bans/[ref]` (запрос `/punishments/public/:ref`, `robots: noindex, nofollow` у обеих страниц).
2. «Настройки → Наказания»: добавлен отдельный блок «Наказания на серверах» (`GET /punishments/me`), существующий список вынесен в блок «Наказания на сайте». Полный текст причины, срок, выдавший, область; отметка о частично скрытом тексте; `linked: false` предлагает привязать аккаунт; фильтр статуса; курсорная пагинация.
3. Состояния: загрузка (aria-busy, текст для скринридера), пусто, ошибка с повтором, 401, 404 (раздел выключен или запись не найдена), 429 с `Retry-After`, 503, `meta.stale`.
4. Навигация: ссылка «Список наказаний» в `FOOTER_PLAYER_LINKS`. Верхнего списка навигации сайта по тому же паттерну нет, в sitemap не добавлена (страница noindex).
5. Клиент API: `ApiError.retryAfterSeconds` (целые секунды 1..3600 из заголовка `Retry-After`; прочие форматы дают `undefined`). Это единственное изменение общего кода клиента, остальное аддитивно.

## Безопасность вывода

- Данные проходят через `toPublicView`/`toMyView` (`apps/web/src/lib/punishments/view.ts`): объект собирается по белому списку, лишние поля (IP, uuid, контакты, в том числе вложенные в `executor`, `scope`, `reason`, `meta`) до разметки не доходят. Тест с «грязным» ответом проверяет отсутствие IP, uuid и e-mail в `innerHTML`.
- Причина выводится дословно как текст React (`reason.label` публично, `reason` в «моих»); без очистки, разметки, `dangerouslySetInnerHTML`, linkify. Тест: `<b>`/`&amp;` остаются буквальным текстом.
- `executor: null` показывается как «Выдавший не указан» (форма ответа не различает причины), консоль как «Консоль». Область: «Глобально», название сервера, «Неизвестный сервер».
- Ссылка на карточку строится только для `ref` по `^(ban|mute)-[1-9][0-9]{0,17}$`; для карточки с неверным `ref` запрос не отправляется.
- Дизайн: только семантические токены (`bg-surface`, `text-muted-foreground`, Badge tone), Lucide, без blur/glass; фокус виден (ring primary), статус дублируется иконкой и текстом.

## Допущения

- Допущение: поиск по нику запускается кнопкой, а не по набору (лимит 60/мин публичного API); фильтры «Тип» и «Статус» применяются сразу.
- Допущение: у публичного списка дефолт `order=desc`, `limit=25` (по контракту), `status` для «моих» без фильтра = все.
- Допущение: `Retry-After` разбирается только как целые секунды; автоповтор по таймеру не делается (кнопка «Повторить» вручную).
- Допущение: привязка к реестру `SITE_MODULES`/`ModuleGate` не делалась (контракт отдаёт решение фронтенду/админке, `packages/shared` трогать нельзя); недоступность раздела определяется ответом 404 `punishments_public_disabled`.
- Допущение: блок обжалования для зеркальных наказаний не показывается (`appealable` всегда false до отдельного среза); ссылка «Обжаловать» осталась только у наказаний на сайте.
- Допущение: `/bans` в sitemap не добавлен, так как страница `noindex`.

## Не сделано и почему

- Карточка персонала и скрытие/раскрытие выдавшего (`admin/punishments`, `issuer-hidden`): вне scope по заданию. Предложение следующему подсрезу: карточка пользователя в `admin/users` (вкладка «Наказания на серверах» по `users.punishments` + 2FA) со списком `GET /admin/punishments?subjectUuid=...`, раздельными действиями «Скрыть выдавшего»/«Показать выдавшего» (диалог с причиной 1-200, видимость кнопок при наличии обоих прав `punishments.issuer.hide` и `users.punishments`, обработка 403 `punishments_issuer_hide_forbidden` и `admin_2fa_required`), и тестами на эти коды.
- Realtime/WebSocket и проверка в браузере: вне scope.

## Риски

- Контракт и реальные ответы API не сверялись запуском (API на этой ветке не поднимался, e2e запрещены): вся логика проверена на моках формы из `packages/shared`. Защитный разбор отбрасывает записи с неожиданной формой, это скрывает расхождения контракта (запись просто не покажется).
- Публичный раздел выключен по умолчанию (404): до включения владельцем `/bans` показывает «Раздел недоступен»; ссылка в футере уже видна. Если включение отложат, ссылку можно скрыть (`available: false`).
- Имена сотрудников и сервера показываются по Q63; отзыв уже отданного имени невозможен (R86).
- Таблица с 8 колонками на узком экране прокручивается по горизонтали (мобильной карточечной раскладки нет).
- `ApiError.retryAfterSeconds` теперь устанавливается для всех ошибок клиента; поведение остальных страниц не меняется (поле только добавляется).

### DECISIONS.md: ADR-0181

```
## ADR-0181 — Фронтенд публичного банлиста и «Наказаний на серверах»: срез 2 этапа 02 (ADR-0180)

Статус: Accepted (реализация на ветке feature/stage-02-s2-bans-web, не смержено).

Контекст. ADR-0180 утвердил контракт API наказаний (публичный список и карточка, `/punishments/me`, персонал). Нужен клиент без входа и блок игрока в настройках.

Решение.
1. `/bans` и `/bans/[ref]` - публичные страницы с `robots: noindex, nofollow`. Список: баны и муты, поиск по префиксу ника (по кнопке, не по набору: лимит 60/мин), фильтры типа и статуса, сортировка по дате, курсорная пагинация (`nextCursor`, без `total`).
2. Рендерится только белый список полей: ответ API приводится к явно собранным объектам (`toPublicView`, `toMyView`); IP, uuid, контакты и любые лишние поля до разметки не доходят, даже если придут в ответе. Причина выводится дословно как текст, без очистки, разметки и автоссылок (принципы 2-3 контракта).
3. «Настройки -> Наказания»: два блока, «Наказания на сайте» (прежний) и «Наказания на серверах» (`GET /punishments/me`, полный очищенный текст причины, отметка скрытой части, `linked: false` ведёт к привязке). Обжалование зеркальных наказаний не показывается (`appealable` всегда false).
4. Состояния по контракту: 401, 404 (раздел выключен/запись не найдена), 429 с `Retry-After`, 503, `meta.stale`. Для `Retry-After` клиент API (`ApiError.retryAfterSeconds`) разбирает целые секунды.
5. `executor: null` - нейтральная подпись «Выдавший не указан» (форма ответа не различает причины); область - «Глобально», название сервера или «Неизвестный сервер».
6. Вне среза: карточка персонала и скрытие выдавшего (следующий подсрез, карточка пользователя в admin/users).

Последствия. Верстка опирается на форму ответа, а не на запуск API (e2e и сборка не запускались). Ссылка в футере ведёт на раздел, выключенный по умолчанию (R105).
```

### RISKS.md: R105-R109

```
## R105 — Ссылка на /bans видна до включения публичного раздела (ADR-0181) — OPEN
Раздел по умолчанию выключен (404 `punishments_public_disabled`, до юридической оценки 152-ФЗ). Ссылка в футере показывается всегда и ведёт на «Раздел недоступен». Митигация: `available: false` у ссылки или включение раздела владельцем. Решает владелец.

## R106 — Защитный разбор скрывает расхождения контракта (ADR-0181) — OPEN
`toPublicView`/`toMyView` отбрасывают записи с неожиданной формой (нет `ref`, `kind`, `status`, `startedAt`, ника). Расхождение клиента и API проявится как «пропавшие» записи, а не как ошибка. Митигация: e2e и ручная проверка на включённом разделе до публикации; тесты на форму из `packages/shared`.

## R107 — Клиент не проверялся против живого API и в браузере (ADR-0181) — OPEN
Тесты на моках (vitest, jsdom); `next build`, e2e и просмотр в браузере (контраст, фокус, мобильная ширина) не выполнялись. Закрыть перед включением раздела.

## R108 — Имя выдавшего и название сервера показываются публично и не отзываются (ADR-0181, R81, R85, R86) — OPEN
Клиент выводит `executor.name` и `scope.name` как есть. Скрытие выдавшего персоналом не отзывает уже отданное браузерам и архивам (кэш до ~50 с на стороне API, внешние копии - бессрочно). Интерфейс скрытия в этом срезе не реализован.

## R109 — Таблица /bans на узком экране только прокручивается (ADR-0181) — OPEN (низкий)
8 колонок; на мобильных горизонтальная прокрутка вместо карточек. Улучшение - отдельным срезом дизайна по решению владельца.
```
