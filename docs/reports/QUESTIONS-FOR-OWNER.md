## Q2. Локальный запрет `gh pr merge *` в `.claude/settings.json`

## Q20. Redis в production: политика памяти

- Этап: B (P3-03a, лимиты compose).
- Суть: Redis ограничен `--maxmemory 192mb --maxmemory-policy noeviction` (mem_limit 256m). В Redis лежат счётчики brute-force, кеш прав, 2FA-состояния, чат. При заполнении запись падает → вход и проверки прав отвечают 500 (fail-closed: обхода лимитов нет, но возможен отказ в обслуживании). Throttler — в памяти процесса, не в Redis.
- Варианты: (а) `noeviction` (целостность счётчиков, риск 500 при заполнении); (б) `volatile-lru` (доступность, но под давлением памяти могут вытесняться счётчики brute-force с TTL); (в) без maxmemory, только mem_limit (OOM-kill контейнера).
- Рекомендация: (а) + мониторинг/алерт памяти Redis при появлении сервера.
- Заблокировано: ничего.
- Допущение: (а); текст ADR-0158 исправляется по итогам ревью.
- Статус: ОТВЕЧЕН (2026-11-17, промпт 08): (а) — Redis `noeviction` + мониторинг памяти при появлении сервера.

## Q64. `/bans`: назначение права на скрытие выдавшего и объём списка для персонала

- Этап: 02, срез 2 (контракт `docs/stage-02/BANS-API-CONTRACT.md`, ADR-0180 — утверждается по итогам ревью).
- (1) Право `punishments.issuer.hide` появится в базе только после выполнения seed каталога прав; в production seed выполняете вы. До этого скрыть выдавшего может только владелец (superuser). Ролей «куратор» в seed нет — «куратор и выше» задаётся тем, каким ролям вы выдадите право. Рекомендация: после выката выполнить seed и выдать право ролям куратора и выше в админке.
- (2) Список наказаний для персонала (до 100 записей за запрос, лимит 120 в минуту) показывает UUID игроков и выдавших без записи в аудит — по вашему ответу Q63 п.5 в аудит пишется только карточка. Рекомендация: оставить так (ваше решение); при необходимости — уменьшить размер страницы.
- (3) Нераспознанный (непривязанный к сайту) выдавший: скрыть его имя может только владелец или персонал с наивысшим приоритетом. Рекомендация: принять.
