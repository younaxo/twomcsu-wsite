## Q2. Локальный запрет `gh pr merge *` в `.claude/settings.json`

## Q20. Redis в production: политика памяти

- Этап: B (P3-03a, лимиты compose).
- Суть: Redis ограничен `--maxmemory 192mb --maxmemory-policy noeviction` (mem_limit 256m). В Redis лежат счётчики brute-force, кеш прав, 2FA-состояния, чат. При заполнении запись падает → вход и проверки прав отвечают 500 (fail-closed: обхода лимитов нет, но возможен отказ в обслуживании). Throttler — в памяти процесса, не в Redis.
- Варианты: (а) `noeviction` (целостность счётчиков, риск 500 при заполнении); (б) `volatile-lru` (доступность, но под давлением памяти могут вытесняться счётчики brute-force с TTL); (в) без maxmemory, только mem_limit (OOM-kill контейнера).
- Рекомендация: (а) + мониторинг/алерт памяти Redis при появлении сервера.
- Заблокировано: ничего.
- Допущение: (а); текст ADR-0158 исправляется по итогам ревью.
- Статус: ОТВЕЧЕН (2026-11-17, промпт 08): (а) — Redis `noeviction` + мониторинг памяти при появлении сервера.

## Q76. GitHub: токен агента действует с правами администратора репозитория (обход rulesets)

- Этап: Git (промпт 10, промпт 04 раздел 1). Проверено read-only 2026-11-17 ~20:30 токеном из отдельного `GH_CONFIG_DIR`.
- Факт: fine-grained токен выпущен от вашей учётной записи (роль Admin). Ruleset `all-branches-integrity` (запрет удаления и force-push) и `tags-protection` имеют bypass для роли Admin в режиме «always» — для этого токена сервер force-push и удаление веток НЕ запрещает; `main-protection` — bypass «pull_requests_only»: прямой push в `main` запрещён, но PR можно слить в обход обязательных проверок. Серверные пробы «не может force-push/удалить ветку» поэтому не пройдут; деструктивные пробы не выполнялись.

- Недостающих прав для работы нет (Administration не нужен: approvals уже 0).
- Варианты: (а) оставить как есть (защита только на стороне агента); (б) машинный аккаунт без роли Admin с правами Write — rulesets будут действовать и на агента (рекомендация runbook); (в) убрать bypass роли Admin в `all-branches-integrity` (тогда и вы не сможете force-push).
- Рекомендация: (б) при ближайшей возможности; до этого — (а).
- Заблокировано: ничего. Допущение: (а).
- Статус: ОТВЕЧЕН (промпт 10 v1.1, 2026-11-17 ~20:45): машинный аккаунт не создавать, токен оставить; принятый риск — RISKS (R126, запись на вершине стека) и runbook agent-github-access.md (650e84f, PR #146); токеном не делать force-push, удаление веток и слияние без трёх зелёных проверок и CLEAN.

## Q85. Возврат денег за уже выданный товар («возврат по ошибке», к подэтапу 0.9)

## Q102. API: прямой импорт multer без зависимости в package.json

- Факт: apps/api/src/modules/files/files.controller.ts импортирует multer, которого нет в apps/api/package.json (есть только транзитивно через @nestjs/platform-express). При запуске собранного API в строгой раскладке pnpm он падает с «Cannot find module multer»; на локальном стенде обойдено через NODE_PATH, код не менялся.
- Допущение: в production-образе это может проявиться так же — проверить при сборке infrastructure/api.Dockerfile. Исправление (добавить multer той же версии, что у @nestjs/platform-express, в dependencies apps/api) меняет lockfile, поэтому делается отдельным PR с полной проверкой CI; без решения владельца ночью не выполняется.
- Статус: ОТКРЫТ.
