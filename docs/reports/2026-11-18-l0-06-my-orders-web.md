# Подэтап 0.6, шаг 2 (Web): «Мои заказы и история в профиле»

Ветка `feature/l0-06-my-orders` (база d89f7cc2). Контракт API — ветка `feature/l0-06-my-orders-api` (646c4906), в эту ветку не мержилась.

## Сделано

1. `/shop/orders` (`apps/web/src/app/(site)/shop/orders/page.tsx`): список своих заказов (номер, дата, сумма, статус оплаты), пагинация по 20, честное пустое состояние («Заказов пока нет», ссылка в магазин), состояния загрузки, ошибки с повтором, анонима. Ссылка строки ведёт на `/shop/orders/[orderNumber]` (страница 0.5). Под `ModuleGate module="store"`.
2. Меню профиля: «Заказы» активно (`/shop/orders`), скрыто при выключенном модуле магазина или его техработах (`useModuleAvailability('store')`, тот же механизм, что у `ModuleGate`). «Избранное» убрано из меню целиком (Q67), а не показано как «скоро».
3. «История покупок»: новый раздел `/settings/purchases` (вкладка в настройках, скрыта при выключенном модуле) с последними 5 заказами и ссылкой «Все заказы».
4. «Последние входы и сессии»: блок «Где выполнен вход» в `settings/security` уже был (`GET /auth/sessions`: устройство, маска IP, дата входа, завершение). Добавлена честная пометка: это активные сессии, журнал завершённых входов не ведётся, IP показан не полностью.

Общие части: `components/store/order-status-badge.tsx` (тон, иконка и подпись статуса; карточка заказа переведена на него), `components/store/orders-list.tsx`, хук `useMyOrders` и тип `OrdersPageView` в `lib/store/checkout.ts`.

## Дизайн и доступность

Solid-поверхности, semantic tokens, Lucide, без blur/glass. Статус передан подписью и иконкой, не только цветом. Строка заказа целиком ссылка с видимым focus ring и высотой не менее 44px, список с `aria-label`, пагинация с именем «Страницы заказов», скелетон с `role="status"` и sr-only текстом.

## Допущения

- Страница списка хранится в `useState`, не в URL (проще, без Suspense для `useSearchParams`).
- Поле `createdAt` в `OrderView` опционально (как было в 0.5); при его отсутствии показывается «Дата неизвестна».
- Статус выдачи не показывается (после 0.7).
- Сотрудник с обходом техработ в меню «Заказы» не видит при выключенном модуле (страница при этом открывается напрямую).
- Фильтр `status` из API в UI не использован (в задаче не требовался).

## Доработки по ревью

`useCreateOrder` после успеха инвалидирует `['store','orders']` (новый заказ виден в списке сразу); ссылка «Войти» в `OrdersList` ведёт с `next` = текущий путь (`usePathname`); оба случая покрыты тестами в `orders.test.tsx`; `settings/layout.tsx` проверен prettier; пагинация ограничена `totalPages`, лимит API `page <= 10000` её не затрагивает.
