## 5. Что осталось / требования к дорожке B (API, apps/api не менялся)

1. «Уже куплено» для уникальных: `GET /store/products/:slug` не отдаёт признак. Нужно поле `alreadyPurchased: boolean` для вошедшего (по `OrderItem` оплаченных заказов). UI уже читает `alreadyPurchased?` и без поля ничего не показывает.
2. Наличие: у `Product` нет остатка/«закончился»; сейчас «нет в наличии» = нет активных вариантов. Если нужен лимит запаса — поле в контракте.
3. `bought-together` возвращает товары без счётчика и только по COMPLETED-заказам; для пустой БД блок скрыт. Достаточно как есть.
4. `GET /store/categories` отдаёт плоский список с `parentId`; UI показывает все активные как чипы без вложенности. Нужна иерархия — решение по каталогу владельца.
5. Поиск `search` — по названию (`contains`), без описания.
6. Ссылка `/shop/cart` в `floating-actions.tsx` остаётся (делается в 0.2); в области 0.1 её нет.

## 6. Решения и допущения

- Допущение: `alreadyPurchased` пока не отдаётся — поле опциональное (см. п. 5.1).
- Допущение: предел количества без `maxPerPurchase` — 99 (только интерфейс, сервер валидирует сам).
- Допущение: фильтры хранятся в состоянии страницы, не в URL (без `useSearchParams`, чтобы не требовать Suspense при сборке); ссылкой на фильтр поделиться нельзя.
- Цена на карточке — минимум активных вариантов; сумма заказа на клиенте не считается (итог — сервер, 0.2).
- Крошка категории на карточке товара ведёт на `/shop` (фильтр по URL не поддерживается, см. выше).

## Риски

- Существующий e2e `store-catalog` не прогонялся; возможна правка селекторов, если он искал заголовок `h2` внутри не-ссылки (теперь заголовок содержит ссылку).
- `has-[:focus-visible]` требует Tailwind с `:has()` (современные браузеры); в старых радио остаётся без кольца, но выбор виден рамкой.
- Данных каталога в БД может не быть до 0.3/0.11 — витрина покажет «Товаров пока нет».

### Требования к токенам и общим компонентам (вне scope)

- tokens.css: для светлой темы нужен --focus-ring с контрастом не менее 3:1 к --background (сейчас --focus-ring = --ring, около 2.9:1), и использование в витрине focus-visible:ring-focus-ring (если Tailwind-алиас будет добавлен). Также граница выбранного/невыбранного состояния на светлой теме (border-border около 1.5:1).
- QueryBoundary: не умеет aria-busy и role=status для скелетона по умолчанию; общий вариант (проп busy/статус) убрал бы локальные обёртки.

### Допущения и риски

- Допущение: ввод больше лимита зажимается сразу (иначе тест/пользователь увидит значение выше max); пустое поле не меняет родительское количество до blur.
- Риск: focus-visible:after:ring-offset на Card может быть обрезан родителем с overflow-hidden (в сетке каталога не обрезается, визуально не проверялось; e2e и сборка не запускались).
- Риск: e2e store-catalog не прогонялся.
- Риск: aria-disabled у +/- — кнопки остаются в Tab-порядке (намеренно).

- ADR-0087: type=number заменён (поле количества: type=text, role=spinbutton, inputMode=numeric, pattern), полный vitest 636/636, tsc без ошибок в src.
