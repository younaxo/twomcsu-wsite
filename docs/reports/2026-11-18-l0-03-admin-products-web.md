## Что сделано

- `/admin/store/products`: список (поиск по названию уходит в API; фильтры статуса и типа — по загруженной странице), пагинация, создание, правка, быстрая активация/деактивация, удаление (мягкое при заказах), предпросмотр карточки (тот же `ProductCard`, что в /shop, внутри `inert`) и полного описания (`SafeMarkdown`).
- Форма товара: тип (при правке не меняется), название, slug (при правке не меняется), краткое и полное описание, категория, картинка (проверка https и хоста на клиенте, как `product-image-url.ts` и `next.config`), валюта и количество для CURRENCY, maxPerPurchase, порядок, сервер, isGiftable / isSelfOnly / isUnique / isSeasonalOnly / isFeatured, активность (только при правке).
- Варианты: при создании — 1–10 строк в теле POST; при правке — каждый вариант отдельным PATCH/DELETE (`store.products.variants`), добавление варианта; срок, цена и старая цена Decimal-строкой (проверка regexp как в API, сравнение без float через BigInt), порядок, активность.
- `/admin/store/categories`: список, создание, правка (название, описание, родитель, порядок, активность), быстрое скрытие/включение, удаление с подтверждением.
- Навигация: группа «Магазин», пункт «Товары магазина» с подразделами «Товары» и «Категории», иконка `ShoppingBag`; пункт виден по `store.products.view` или `store.categories.view`.
- PermissionGate: `store.products.view`, `store.categories.view`; кнопки — по `create/edit/delete/variants`. Без права на правку диалог товара открывается только для чтения.
- Ошибки: 403 (недостаточно прав), 403 `admin_2fa_required` (сообщение и ссылка «Включить 2FA» на `/settings/security`), 409 slug / длительность варианта у поля, 409 `PRODUCT_IN_BUNDLE` / `VARIANT_IN_BUNDLE`, 422 `PRODUCT_TYPE_NOT_SELLABLE` (у переключателя активности и в toast), 400 валидации — по полям.
- Поле «выдача» и gameCommands не показываются и не отправляются; в форме справочная пометка «настраивается владельцем в подэтапе 0.11». При создании `isActive` не отправляется.

## Ревью Q&S и доработки

### Статус

- **B1 (товар, категория) — сделано.** При неверной клиентской валидации фокус уходит на первое невалидное поле (`aria-invalid="true"`, `aria-describedby` на текст ошибки); в форме одна сводка с `role="alert"` (`FormErrorSummary`). Раньше каждая ошибка поля тоже была `role="alert"` (в `ui/Field`) и дублировала сводку. Теперь формы используют `FormField` (`apps/web/src/components/admin/form-field.tsx`): тот же вид и те же aria-связи, но текст ошибки поля без `role="alert"`. Общий `ui/Field` не менялся (вне назначенной области, его используют другие экраны). Ошибка `isActive` в форме товара и `listError` редактора вариантов тоже перестали быть alert; у `Switch` выставляются `aria-invalid` / `aria-describedby`.
- **B2 (редактор вариантов) — сделано.** Черновики вариантов при создании товара: фокус на первом невалидном поле варианта, сводка формы одна. Правка варианта и добавление нового варианта (отдельные запросы): у каждой строки своя сводка `role="alert"` и фокус на первом невалидном поле. Серверная ошибка варианта показывается той же сводкой, toast с тем же текстом убран (дубль для screen reader).
- **B3 — частично, решение ниже.**
- **409 удаления категории.** `describeStoreAdminError` разбирает `CATEGORY_HAS_CHILDREN` и `CATEGORY_HAS_PRODUCTS` (отдельные русские сообщения), прочие 409 идут по общему фолбэку (текст API, по умолчанию «Конфликт данных»). Старый 400 по-прежнему показывает текст API.
- **https для картинок.** В форме категории нет полей `image`/`icon`, клиентской валидации для них не требуется. В форме товара уже есть проверка https и хоста (`isAllowedProductImageUrl`, список хостов дублирует API и `next.config`, как и раньше); серверный 400 по картинке привязывается к полю и получает фокус.

### Решение по B3

API (c90eccf, `ValidationPipe` + class-validator) для 400 отдаёт только `message: string[]` без поля или машинного кода; `code` есть только у доменных ошибок (409/422/403). Привязка по полю/коду невозможна, поэтому оставлена существующая эвристика `FIELD_MATCHERS` по тексту сообщения; всё, что не сопоставилось, попадает в общую сводку. Все привязанные серверные ошибки теперь тоже получают фокус и сводку. Если API начнёт отдавать `details` с полями, `describeStoreAdminError` нужно перевести на них.

### Допущения

- Сводка показывает число ошибок, а не их перечень: тексты есть у самих полей и связаны через `aria-describedby`.
- Для невалидных кнопок (нет вариантов) используется `data-invalid="true"`, так как `aria-invalid` к кнопке неприменим.
- Серверные ошибки `price`/`duration` в форме товара по-прежнему идут общим сообщением (поля вариантов в create-режиме не получают их по ключу).

### Риски

- Фокус переводится эффектом после рендера; в браузере вручную не проверялся (только jsdom).
- `FormField` повторяет разметку `ui/Field`; при изменении `Field` стоит сверить или добавить в `Field` опцию без `role="alert"` (решение владельцу дизайн-системы).
- Эвристика сопоставления 400 с полями зависит от текста сообщений API.

- ADR-0087: type=number заменён (поле количества витрины: type=text, role=spinbutton, inputMode=numeric, pattern), полный vitest 707/707, tsc без ошибок в src.
