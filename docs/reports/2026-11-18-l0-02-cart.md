## 5. Требования к дорожке B (API; apps/api не менялся)

1. `GET /store/cart` падает 400, если сохранённый промокод стал недействителен (истёк, исчерпан, сумма ниже минимума): `computeTotals` бросает исключение — корзина целиком недоступна. Аналогично `PATCH`/`DELETE` позиций после изменения количества могут вернуть 400 уже после сохранения. Нужно: GET не падает, отдаёт `promoCode` + `promoError` и total без промокода, либо сервер сам снимает недействительный код. UI сейчас обходит это отдельным состоянием «Убрать промокод».
2. `lines[]` не содержат `cartItemId`; UI сопоставляет по индексу (порядок совпадает, длины сверяются). Нужен `cartItemId` в строке.
3. Позиции корзины не отдают `slug`, изображение, длительность варианта (`variant.duration`), `maxPerPurchase`. Нужны для ссылки на товар, картинки, подписи варианта и предела количества (сейчас предел показывает сервер ошибкой).
4. Подарок: ответ содержит только `giftToUserId`, ника получателя нет. Нужен `giftToUser: { username }`; пока ник помним на странице (после перезагрузки показывается «Подарок»).
5. `POST /store/cart/items` не сливает одинаковые варианты (каждая добавка — новая строка), не проверяет `isUnique` (в корзину можно положить уникальный товар повторно) и `maxPerPurchase` суммарно. UI это обходит (PATCH существующей строки, блок уникального), но защита нужна на сервере.
6. `promoCode` в ответе корзины отдаётся целиком (`maxUses`, `usedCount`, лимиты) — N2 бэклога; UI использует только `code` и `description`. Нужен белый список.
7. `loyaltyDiscountPercent` отдаётся без указания порога/причины; для подсказки «до следующего уровня» нужны данные уровней (не в 0.2).

## 6. Решения и допущения

- Допущение: суммы — строки Decimal, форматируются `formatMoney`; знак «−» у скидок — отображение, расчётов нет.
- Допущение: «Оформить» не ведёт на заглушку, а неактивна с пояснением (оплата — 0.5). Поповер ведёт на `/shop/cart#checkout`.
- Допущение: подарок доступен для позиций-товаров с `isGiftable && !isSelfOnly` (флаги из `lines`); наборы (bundle) не дарятся в UI.
- Допущение: валидация ника получателя — на сервере (404 «Получатель подарка не найден» показывается у поля).
- Допущение: количество у уникального товара не редактируется (всегда 1).
- Допущение: сообщения ошибок API (русские) показываются как есть; 429 и 5xx — общие тексты.

## Риски

- Состояние при недействительном промокоде зависит от текста ошибки (`/промокод|минимальн/i`) — хрупко, пока нет кода ошибки (п. 5.1).
- Сопоставление позиция↔строка по индексу (п. 5.2): при расхождении длин цены не показываются.
- Существующие e2e корзины/магазина не прогонялись; e2e для `/shop/cart` и промокодов не дописаны (по заданию e2e не запускать) — нужно дополнить в дорожке e2e.
- Ссылка поповера «Оформить» теперь дублирует «Перейти в корзину» до появления 0.5.
- Ник подарка не переживает перезагрузку страницы (п. 5.4).
