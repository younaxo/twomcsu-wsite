## 9. Исправления по ревью

- M3 (backup.sh, ротация): теперь по метке, регулярное выражение `twomc-<UTC>-<тег>` без пересечения суффиксов (`pre` не трогает `x-pre`); сбой `rm` даёт предупреждение и не меняет код возврата. Стаб до исправления: KEEP=2 удалял `predeploy`/чужие метки, `rm` fail давал выход 1 вместо 4. После: predeploy сохранён, daily=2, rm fail + S3 fail -> 4, rm fail -> 0.
- M4 (restore.sh --target prod): ввод имени БД при TTY; без TTY нужны `RESTORE_CONFIRM` и `--non-interactive`; отказ при запущенном api; обязательный снимок текущей БД до `pg_restore --clean`, неудача -> стоп (выход 1). До исправления: без TTY с одним `RESTORE_CONFIRM` восстановление выполнялось (выход 0).
- Low: runbook отмечает, что `SHA256SUMS` и манифест защищают от повреждения, не от подмены; подпись — будущее.
- Допущение по политике prod-restore: без TTY нужны оба условия; снимок — только БД, открытый дамп с ПДн в `RESTORE_SNAPSHOT_DIR`. Решение владельца не принято.
- Проверки: `bash -n` и shellcheck rc=0 на трёх скриптах; стаб-набор 30 из 30 (регрессия: sha256 mismatch -> 2, нехватка места -> 3 для backup и restore, без S3 -> 0, S3 сбой -> 4, drill-restore -> 0). Ограничение: TTY-ветку в Git Bash на Windows не эмулировать (нет pty), интерактивный ввод проверен через копию скрипта с отключённым `-t` и вводом по stdin; сама проверка `-t 0 && -t 1` не тестировалась.

## 10. Исправления по ревью C

Каждая находка — отдельный коммит ветки `chore/p3-03b-backup-restore`.

- Low, `backup.sh` (e3f891e): ошибка `rm` при ротации теперь даёт выход 5 (бэкап сохранён); при провале S3 остаётся 4. Стаб: rm fail без S3-сбоя -> 5, rm fail + S3 fail -> 4.
- Low, `restore.sh` (58812db): проверка «api остановлен» учитывает running, restarting, paused. Стаб с моделью статусов: все три состояния -> отказ 1, `pg_restore` не вызван; api остановлен -> 0.
- Low, `restore.sh` (4775e6b): `pg_restore --clean --if-exists --single-transaction` (атомарно). С `-j` несовместим, но `-j` не используется (дамп со stdin); globals не затрагиваются. `RESTORE_SINGLE_TRANSACTION=0` отключает с предупреждением. Ограничение: реальным PostgreSQL не проверено (Docker запрещён), проверит restore-drill.
- M-2, снимок pre-restore (809bbfe): (a) каталог внутри репозитория (в т.ч. относительный путь, корень репозитория, после разрешения ссылок) -> отказ до изменений, каталог не создаётся; (b) с `AGE_RECIPIENT` снимок шифруется (`.dump.age`), без него открытый файл и предупреждение со сроком 7 дней (`RESTORE_SNAPSHOT_PLAIN_DAYS`); при сбое age — стоп, частичного файла нет; (c) ротация `RESTORE_SNAPSHOT_KEEP` (3) отдельно от плановых бэкапов, чужие файлы и плановые бэкапы не тронуты, KEEP=0 -> отказ.
- Допущения: срок открытого снимка 7 дней только в предупреждении (автоудаления нет, работает ротация по числу); код 5 выбран как новый (4 приоритетнее); `--single-transaction` включён по умолчанию и для drill.
- Проверки: `bash -n` и shellcheck rc=0 на backup.sh и restore.sh; старый набор 30 из 30 (с обновлённым ожиданием rm fail -> 5); новый набор для ревью C 41 из 41 (стабы docker, df, rm, age; без Docker). Тексты runbook и ADR-0159 обновлены; последние 3 строки ADR-0159 не менялись.
