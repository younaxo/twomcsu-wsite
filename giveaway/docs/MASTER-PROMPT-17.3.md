# MASTER-PROMPT 17.3 — розыгрыш «Анархия Новой Эры», фаза 3, работа 1 (бэкенд: админка, розыгрыш, эфир, тестовый режим)

Источник: `docs/agent-prompts/17-GIVEAWAY-PHASES-2-3.md` (раздел ФАЗА 3, пп. 1-5). Блок ТРЕБОВАНИЙ сохранён дословно из handoff chief (рекомендации chief; отклонение - с обоснованием в ADR-G003).

ТРЕБОВАНИЯ:
1. Админ-вход Discord OAuth2: authorization code + PKCE + state (одноразовый, в Redis, TTL 10 мин), scope identify; client id/secret и redirect URI — из env (GIVEAWAY_DISCORD_CLIENT_ID/SECRET/REDIRECT_URI), allowlist — env GIVEAWAY_ADMIN_DISCORD_IDS (ровно ID через запятую; пусто -> вход закрыт, fail closed). Допущение: требовать mfa_enabled=true у Discord-аккаунта (/users/@me) — замена правила 2FA админов (Q22); без MFA — отказ. Сессия: случайный токен, в БД только хэш, cookie HttpOnly, Secure, SameSite=Strict, host-only на админ-поддомене (допущение admin.giveaway.twomc.su), idle 30 мин, абсолютный срок 8 ч, выход. Проверка Origin/CSRF для всех изменяющих запросов. Лимиты на вход. Аудит: таблица giveaway_admin_audit (кто, действие, объект, время, без секретов), запись на каждое изменение и вход/выход/отказ. Все три админа имеют все права — допущение. Создавать новые розыгрыши через API нельзя.
2. Админ-API (префикс /api/giveaway/v1/admin/*): список билетов (поиск по нику/билету, пагинация), настройки (порог — только вниз после старта, даты до старта; правило уже есть в сервисе), призы (CRUD: название, количество, изображение — ВЫБОР из статических PNG в giveaway/prizes/ по имени файла, без загрузки; валидация имени по списку разрешённых), профиль игрока (сумма минут и разбивка по дням по МСК).
3. Розыгрыш: после cutoffAt — заморозка снимка: упорядоченный список билетов (ticket, playerUuid, playerName) -> канонический JSON -> SHA-256 = snapshotHash; публикуется хэш. «Рассчитать» (тело содержит snapshotHash и фразу-подтверждение; необратимо; ровно один раз — уникальное ограничение/статус в БД под транзакцией): seed = 32 байта CSPRNG; детерминированная перестановка (Fisher–Yates с индексами из HMAC-SHA256(seed, snapshotHash‖counter) с отбрасыванием смещения) -> порядок; места по призам (количество приза = число мест) в порядке приоритета призов. Публикуются seed, snapshotHash, алгоритм, порядок. Результат сначала только в админке (предпросмотр), затем «Показать в эфире». Дисквалификация: админ отмечает победителя «дисквалифицирован» (причина, аудит) -> место получает следующий билет той же перестановки, ещё не выигравший и не дисквалифицированный. Дисквалификация после эфира допускается, отражается в публичных итогах.
4. Эфир: «Показать в эфире» -> событие всем открытым страницам: SSE GET /api/giveaway/v1/stream (text/event-stream, heartbeat-комментарии ~15 с, Redis pub/sub для нескольких инстансов, ограничение числа соединений на IP), запасной GET /api/giveaway/v1/public/results (опрос раз в 5 с). Публично только ник и билет (+ название приза, картинка по имени файла); seed/snapshotHash/порядок публичны после эфира.
5. Тестовый режим (флаг GIVEAWAY_TEST_MODE_ENABLED, только админам): изолированные данные — тест никогда не затрагивает реальные таблицы/строки. Рекомендация: отдельный «контекст» (contestId/контекст или таблицы test_*), все запросы реального режима жёстко фильтруются по live; тестовое время нику (только в тесте; в реальном режиме ручное начисление отключено и доказано тестом), тестовые билеты, пробный «Рассчитать» и эфир (сброс только тестового контекста). Публичная страница теста — только для админ-сессии, с меткой «ТЕСТ» (контракт для web). Тесты: реальный режим не видит тестовых данных и наоборот.
6. Expand-only миграция apps/api/prisma/migrations/<ts>_giveaway_phase3 (SQL вручную, Q28; НЕ применять — Docker выключен; только `prisma generate`). Только добавления, существующие колонки не менять.
7. GIVEAWAY_ONLY: новые модули/контроллеры входят в список режима (см. giveaway-only.spec.ts и app.module.ts).
8. Логи без токенов, кодов OAuth, секретов, IP.
9. giveaway/prizes/README.md: место для PNG владельца (PNG, <= 2 МБ, имена файлов).
