# ADR-G001 — подсчёт времени онлайн и контракт событий (розыгрыш, фаза 1)

Статус: принято (допущения помечены). Дата: 2026-11-19.

## Решения

1. **Минута-корзина.** Единица учёта — пара (`playerUuid`, минута UTC = `floor(occurredAt)` до минуты). Корзина создаётся только heartbeat с `active=true`. Уникальность пары (PK `giveaway_minutes`) даёт идемпотентность повторов и слияние пересечений (два пульса в одной минуте, два сервера, дослать очередь дважды) без двойного счёта. Рекомендация chief принята без отклонений.
2. **Итог игрока** = число корзин с `startAt <= minute <= cutoffAt`. Корзины вне окна хранятся, но не считаются (окно можно менять в допустимых пределах).
3. **join/quit** — только журнал сессий (`giveaway_session_events`, уникальность (сервер, `eventId`)); в итог не входят. Время не берётся из разницы join/quit (устойчиво к потерянным quit).
4. **AFK** определяет плагин: 5 минут без движения, чата, команды, взаимодействия (порог в конфиге плагина). Пульс раз в минуту; `active=true`, если за последнюю минуту игрок не был AFK.
5. **Время.** В БД и протоколе — UTC. Старт 22.11.2026 00:00 МСК = `2026-11-21T21:00:00Z`; отсечка 30.12.2026 23:59:59 МСК = `2026-12-30T20:59:59Z`; `Europe/Moscow` (UTC+3, без перехода на летнее время). Игрокам — строки «ДД.ММ.ГГГГ ЧЧ:ММ:СС по МСК».
6. **Настройки**: строка `giveaway_settings` (id `default`) или значения по умолчанию из env (без seed). Порог 3000 мин (50 ч). После старта порог можно только понижать; старт после начала не сдвигается (допущение). Поднять порог одновременно с переносом старта «в прошлое» нельзя.
7. **Сервер** определяется только по ключу (`key-id`), не по телу; не из `allowedServers` — 403 (после проверки подписи).

## Контракт для плагина

`POST https://<домен>/api/giveaway/v1/events`, `Content-Type: application/json`, без сжатия, без query. Тело ≤ 64 КБ, ≤ 100 событий.

Заголовки: `X-Giveaway-Key-Id: <id сервера>.<версия>` (id: `^[a-z0-9][a-z0-9-]{1,31}$`, версия 1..999999), `X-Giveaway-Timestamp` (секунды UTC, 10 цифр), `X-Giveaway-Nonce` (22..43 символа `[A-Za-z0-9_-]`, одноразовый, случайный), `X-Giveaway-Signature` (64 hex).

Ключ: `key = HKDF-SHA256(ikm = GIVEAWAY_MASTER_SECRET (UTF-8), salt = id сервера (UTF-8), info = "twomc-giveaway" 0x00 "v1" 0x00 u32be(версия), L = 32)`. Плагин получает готовый `key` (hex) в конфиге; мастер-секрета у плагина нет.

Подпись: `hex(HMAC-SHA256(key, canonical))`, `canonical` = строки через `\n`:
`twomc-giveaway-v1`, `key-id`, `timestamp`, `nonce`, `METHOD` (`POST`), `path`, `sha256hex(сырое тело)`. `path` ВСЕГДА `/api/giveaway/v1/events` (даже если прокси срезает `/api`). Подписывается ровно те байты, что отправляются.

Окно времени ±300 с от часов сайта (часы сервера должны быть синхронизированы по NTP). Нонс — одноразовый (TTL 660 с). Ротация: принимаются текущая и предыдущая версия ключа (`GIVEAWAY_KEY_VERSION`, `GIVEAWAY_ACCEPT_PREVIOUS_KEY`).

Тело:
```json
{"schema":"twomc.giveaway.v1","events":[
 {"eventId":"<uuid>","type":"join|quit","playerUuid":"<uuid>","playerName":"Steve","occurredAt":"2026-11-22T10:00:05.123Z"},
 {"eventId":"<uuid>","type":"heartbeat","playerUuid":"<uuid>","playerName":"Steve","occurredAt":"...Z","active":true}
]}
```
Строго: лишние поля запрещены; `active` — только и обязательно у `heartbeat`; `playerName` `^[A-Za-z0-9_]{1,16}$`; `occurredAt` только UTC (`Z`), формат `YYYY-MM-DDTHH:MM:SS[.sss]Z`; `eventId` — UUID, плагин генерирует один раз и сохраняет в очереди (повтор безопасен). Ошибка схемы отклоняет весь пакет (422 `invalid_envelope`) — плагин не должен повторять такой пакет, а логировать и отбросить.

События с `occurredAt` позже «сейчас + 120 с» или старше 72 ч не принимаются (в ответе `rejected`); локальную очередь плагин досылает в этих пределах, старше 72 ч — отбрасывает.

Ответы: `200 {"accepted":N,"rejected":[{"eventId":"..","reason":"too_old|in_future"}]}` (события в `rejected` повторять не нужно; дубликаты считаются принятыми); `401 {"error":"unauthorized"}` (подпись, время, нонс, версия ключа — без причины); `403 {"error":"forbidden"}` (сервер не разрешён); `413`; `422`; `429` + `Retry-After`; `503` + `Retry-After` (выключено, не настроено, Redis/БД недоступны) — повторять с экспоненциальной задержкой, очередь не терять. Лимиты на сервер: 120 запросов и 3000 событий в минуту.

## Данные и безопасность

Таблицы: `giveaway_settings`, `giveaway_players` (последний ник), `giveaway_minutes`, `giveaway_session_events` (миграция `20261119120000_giveaway_phase1`, expand-only). Логи — только код причины и `key-id`; подписи, ключи, тело, нонсы и IP игроков не логируются (IP игроков в протоколе нет).

## Риски и допущения

- Подмена ника: подлинность игрока = `playerUuid` от плагина. При `online-mode=false` UUID офлайн-детерминирован от ника, и чужой ник можно занять; нужен `online-mode=true` или плагин авторизации (проверка режима — отдельный пункт, в QUESTIONS).
- Компрометация ключа сервера позволяет начислять время: ротация версии ключа, мастер-секрет только у владельца.
- Допущения: AFK 5 мин; лимиты на сервер; запрет сдвига старта после начала; хранение пульса только как корзины (сырые heartbeat не журналируются).
