# MASTER-PROMPT 17.1 — розыгрыш «Анархия Новой Эры», фаза 2, работа 1 (бэкенд: коды и билеты)

Источник: `docs/agent-prompts/17-GIVEAWAY-PHASES-2-3.md` (разделы ПАРАМЕТРЫ и ФАЗА 2). Блок ТРЕБОВАНИЙ сохранён дословно из handoff chief (рекомендации chief; отклонение — с обоснованием в ADR-G002).

ТРЕБОВАНИЯ:
1. Сессия браузера: анонимная cookie розыгрыша (случайный >=128 бит токен, в БД/Redis только хэш; HttpOnly, Secure, SameSite=Lax, путь /api/giveaway, срок ~1 сутки). Без привязки к аккаунтам сайта.
2. POST /api/giveaway/v1/codes (публичный): выдаёт код 16 символов, алфавит Crockford без I, L, O, U (32 символа, 80 бит, crypto.randomInt/randomBytes без смещения), формат XXXX-XXXX-XXXX-XXXX; хранится только HMAC-SHA256(ключ из HKDF мастер-секрета, info отдельный от ключей серверов, нормализованный код); TTL 10 мин; один активный код на сессию («Новый код» аннулирует прежний); лимиты Redis по IP, по IPv6 /64 (переиспользуй существующий хелпер /64 в apps/api, если есть — найди точечно), по сессии; Turnstile — допущение: выключен флагом GIVEAWAY_CAPTCHA_ENABLED по умолчанию, при включении проверяется существующим сервисом Turnstile только если он доступен в GIVEAWAY_ONLY — иначе записать как ограничение. Код возвращается один раз в ответе; не логируется.
3. GET /api/giveaway/v1/codes/status (по cookie): pending (expiresAt) | redeemed {ticket, playerName} | expired — только для владельца сессии. Опрос раз в 2–3 с, лимит на сессию. Публичный GET /api/giveaway/v1/public — ход розыгрыша: даты (UTC + строки «по МСК»), порог, число выданных билетов, статус (до старта/идёт/завершён); без персональных данных.
4. POST /api/giveaway/v1/redeem — подписан HMAC сервера (тот же guard, что events; разрешённый сервер — только «Анархия Новой Эры» по настройке), тело {code, playerUuid, playerName}. Порядок строго: лимит по UUID и по серверу -> если у игрока уже есть билет -> вернуть его (и, если код валиден и не погашен, привязать код к этому билету, чтобы страница показала билет) -> если время < порога -> {status:"not_enough", minutes, remainingMinutes} БЕЗ проверки кода -> иначе проверка кода: невалиден/просрочен/погашен/чужой -> единый ответ {status:"invalid_code"} без различий -> валиден -> в одной транзакции: создать билет (если нет), погасить код (одноразовость под конкуренцией: условный update/уникальность), привязать ник+UUID -> {status:"issued", ticket}. Ответы не раскрывают существование чужих кодов; время отклика не должно заметно различаться по ветвям кода (постоянное сравнение HMAC, без раннего выхода по БД, где разумно).
5. Билет: буква из A–Z без I и O (24) + три цифры (000–999), CSPRNG, UNIQUE в БД, повтор при коллизии (ограниченное число попыток, затем 503), один билет на UUID (UNIQUE), выдаётся сервером до анимации. Розыгрыш только среди билетов. Билеты выдаются только между startAt и cutoffAt (вне — понятный статус).
6. Прогресс для плагина: в ответе POST /events (или отдельный подписанный GET /api/giveaway/v1/progress?uuid=... пакетно) — по игрокам: minutes, thresholdMinutes, remainingMinutes, percent, qualified, ticket|null. Нужно для плейсхолдеров и уведомления о пороге. Совместимость с плагином фазы 1 (старые поля ответа не ломать).
7. Учёт только с разрешённого сервера «Анархия Новой Эры» — проверить, что подсчёт минут/порога идёт только по нему (по настройке allowed servers); если в фазе 1 это не так — исправить и отметить.
8. Expand-only миграция (новые таблицы codes, tickets, browser sessions при необходимости), SQL вручную, Q28; применять только на одноразовой БД — сейчас НЕ применять (Docker выключен).
9. Логи без кодов, токенов сессий, IP.
10. Попутно: заменить giveaway.example.com на giveaway.twomc.su в giveaway/deploy/nginx/giveaway.conf и giveaway/deploy/RUNBOOK.md (в RUNBOOK пометку «шаг владельца по домену» заменить на «DNS-запись giveaway в Beget — владелец»).

ОБЛАСТЬ ЗАПИСИ: apps/api/src/modules/giveaway/**, apps/api/prisma/schema.prisma (только новые модели/отношения к новым), одна новая миграция apps/api/prisma/migrations/<ts>_giveaway_phase2/ (SQL вручную, expand-only), apps/api/src/config/env.validation.ts (только ключи GIVEAWAY_*), giveaway/docs/**, giveaway/deploy/nginx/giveaway.conf и RUNBOOK.md (только домен), giveaway/README.md (кратко).
